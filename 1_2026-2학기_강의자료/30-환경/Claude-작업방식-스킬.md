# Claude 작업 방식 — 볼트 스킬 두 개

## 이 문서가 있는 이유

- 지금까지의 작업 방식(문서 골격·문체·수식·모델 생성·VRX 검증)이 **대화 기록에만** 있었음
- 대화가 끝나면 사라짐 → 다음 학기에 같은 시행착오를 반복하게 됨
- **스킬 파일로 고정**해서 볼트와 함께 저장. Dropbox 로 다른 PC 에도 따라감
- 결과: **지시 한 줄이면 같은 품질로 재현**됨

---

## 1. 무엇이 만들어졌나

| 스킬 | 무엇을 담고 있나 |
|---|---|
| **`capstone-lecture-vault`** | 강의자료 작성·문체·수식·PDF·그림·VRX 검증·볼트 유지 |
| **`simulink-gnc-models`** | Simulink 모델 생성·배치 정리·GNC 규약·모델 검증 |

- 위치 — 볼트 안 `.claude/skills/`
- Claude Code 가 **이 폴더에서 자동으로 인식**함. 별도 설정 불필요
- 형식 규칙의 원본은 여전히 `CLAUDE.md`. 스킬은 **실행 절차**를 담음

### 파일 구성

```
.claude/skills/
├── capstone-lecture-vault/
│   ├── SKILL.md                     지시 -> 첫 동작 대응표, 불변 규칙 6개, 작업 루프
│   ├── references/
│   │   ├── lecture-md.md            주차 자료 골격, 대상 독자, 개조식, 교재 어조, 과제 배점
│   │   ├── pdf-and-math.md          md2pdf 실행, LaTeX 수식, 템플릿 내부 동작과 오류 대처
│   │   ├── figures-svg.md           SVG 규칙, 팔레트, 그림 읽는 법
│   │   ├── vrx-runbook.md           WSL 환경, 외란 유무, 실험 설계, 반복되는 오류 6종
│   │   └── vault-upkeep.md          프론트매터, 링크, 지식카드, 색인 갱신, 주차 재배치
│   └── scripts/vault_check.sh       볼트 점검 (8항목)
└── simulink-gnc-models/
    ├── SKILL.md
    ├── references/{layout, build-models, gnc-conventions, verify}.md
    └── scripts/{tidy_layout, tidy_all}.m
```

## 2. 쓰는 법 — 지시만 하면 됨

스킬 이름을 부를 필요가 없음. 아래처럼 말하면 해당 절차가 자동으로 적용됨.

| 이렇게 지시하면 | 무엇이 자동으로 따라오나 |
|---|---|
| "11주차 자료 만들어줘" | 템플릿 골격 유지 · 초보자 기준 서술 · 진도 체크 · 과제 배점표(검증 30% 이상) · PDF |
| "이 절 설명 보강해줘" | 용어 첫 등장 설명 · 정상 출력 예시 · 클릭 경로 생략 금지 |
| "문체 고쳐줘" | 금지 표현 자동 검사 후 치환. 코드블록 정렬은 건드리지 않음 |
| "수식 넣어줘" | LaTeX 으로 작성. Obsidian·GitHub·PDF 세 곳에서 렌더 |
| "그림 그려줘" | `assets/` 에 SVG · 흰 배경 · 팔레트 통일 · 그림 읽는 법 표 |
| "모델 만들어줘" | `build_wXX_models.m` 생성 · `tidy_layout` 2회 · 색 규칙 · PNG 추출 |
| "선이 복잡해, 정리해줘" | 겹침 0 을 목표로 배치 정리 후 결과 보고 |
| "VRX 로 확인해줘" | 배포판 `Ubuntu-22.04` 확인 · RTF 측정 · 페이싱 · 실행 후 프로세스 정리 |
| "오프라인이랑 대조해줘" | 겹치는 구간만 비교 · 위상 오차 여부 판별 |
| "다 끝났나 확인해줘" | 점검 스크립트 실행 |

### 직접 돌려 볼 수 있는 것

```bash
bash .claude/skills/capstone-lecture-vault/scripts/vault_check.sh
```

- 8개 항목을 세어서 표로 보고함. **전 항목 0 건**이 합격선

| 항목 | 무엇을 잡나 |
|---|---|
| 1 | MD 는 고쳤는데 PDF 를 안 뽑은 문서 |
| 2 | 대상이 없는 wikilink |
| 3 | 파일이 없는 그림 참조 |
| 4 | VSCode·GitHub 에서 깨지는 Obsidian 전용 임베드 |
| 5 | 금지 표현 (`여러분`·`우리`·`오늘`·`함정`·`★` 등 8종) |
| 6 | GitHub 에서 깨지는 콜아웃 종류 |
| 7 | 흰 배경이 없어 다크 모드에서 안 보이는 SVG |
| 8 | 남아 있는 백업 파일 |

- 문체만 보려면 `--style`, 링크·그림만 보려면 `--links`
- 코드블록과 인라인 코드 안은 검사에서 제외됨 (규칙을 인용한 문장이 걸리지 않게)

> [!note] 도입 시점에 실제로 잡힌 것
> 2026-09-04 최초 실행에서 지적 사항 **34건**. 강의계획서·지식카드·환경구축 문서에 남아 있던
> `우리`·`오늘의`·`함정`·`★` 표현 12곳을 수정하고, PDF 3개를 재생성해 **0 건**으로 맞춤.

## 3. 규칙을 바꾸고 싶을 때

| 바꿀 것 | 고칠 파일 |
|---|---|
| 문서 형식·문체·폴더 구조 | `CLAUDE.md` (원본) |
| 실행 절차·체크리스트 | 해당 스킬의 `SKILL.md` 또는 `references/*.md` |
| 점검 항목·금지 표현 목록 | `scripts/vault_check.sh` 의 `words=(...)` |
| 모델 배치 알고리즘 | `simulink-gnc-models/scripts/tidy_layout.m` |

- 배치 알고리즘은 **고치기 전에 `references/layout.md` 를 읽을 것**.
  이미 확인된 실패 사례 8종이 표로 정리돼 있음

---

## 4. 다른 PC 에서

- 스킬이 볼트 안에 있으므로 **Dropbox 동기화만으로 따라감**
- 필요한 것은 이 폴더에서 Claude Code 를 여는 것뿐
- 사용자 계정 쪽(`~/.claude/skills/`)에는 이 볼트용 스킬을 두지 않음 — 사본이 둘이면 갈라짐

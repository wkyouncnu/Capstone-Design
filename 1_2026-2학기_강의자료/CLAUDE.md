## 0. 산출물 형식 — 먼저 읽을 것

> [!important] 확정 사항 (재확인 불필요)
> - **강의자료는 Markdown 으로만 만든다**
> - **HTML 슬라이드 덱은 만들지 않는다.** 요청받지 않는 한 `html-slide-deck` 스킬을 쓰지 말 것
>   - `10-주차별-강의자료/W01_슬라이드.html` 은 이전에 만든 것. 유지하되 확장하지 않는다
> - 배포는 **MD + PDF 쌍**. MD를 고쳤으면 **반드시 PDF도 다시 생성**
> - 그림은 **`assets/` 폴더의 SVG**, 표준 마크다운 링크로 삽입

**PDF 생성 — 이 한 줄이 전부다**

```bash
bash _tools/md2pdf.sh 10-주차별-강의자료/W0*.md
```

- 인터넷 불필요 (`_tools/marked.min.js`, `_tools/mathjax-tex-svg.js` 로컬 사본 사용)
- 서식은 `_tools/pdf-template.html` 의 `<style>` 하나가 기준
- 상세는 [[MD를-PDF로-내보내기]]
- Chrome 은 Windows 실행 파일이라 **POSIX 경로를 못 읽는다**.
  스크립트가 `cygpath` 로 변환해 넘긴다 — 다른 Chrome 호출을 추가할 때도 같이 처리할 것

### 수식은 LaTeX 으로 쓴다

- 인라인 `$y_e$`, 블록 `$$ ... $$`
- Obsidian·GitHub·PDF **세 곳에서 모두** 렌더된다 (PDF 는 로컬 MathJax 로 SVG 조판)
- 템플릿이 **코드블록을 먼저 보호**하므로 `$HOME`, `$(pwd)` 는 수식으로 잡히지 않는다
- 긴 유도는 블록 수식, 코드에 그대로 쓰이는 식은 코드블록 — 둘을 섞지 않는다

## 2. 절대 규칙

1. **`10-주차별-강의자료/` 와 `80-과제/` 는 학생이 그대로 받는 파일이다.**
   내부용 메모, 미확정 계획, 채점의 뒷사정을 쓰지 않는다. 그건 `00-운영/` 에 쓴다.
2. 문서를 추가·이동했으면 **`README.md` 의 표를 손으로 갱신한다.** 자동 인덱스 스크립트는 없다.
3. `40-자산/` 의 수치·파일명을 추측으로 채우지 않는다. **확인한 것만** 쓴다.
4. MD를 고쳤으면 **PDF도 다시 내보낸다.** 두 파일이 어긋나면 학생이 혼란스러워한다.
5. **폴더명의 대괄호 주의** — PowerShell이 와일드카드 문자클래스로 해석한다.
   `Resolve-Path`, `Get-Item`, `Copy-Item` 등에 `-LiteralPath` 를 쓸 것.
   Bash의 `find -path "./[2025]*"` 도 같은 이유로 오작동한다.
   - 볼트 폴더 자체는 2026-09-05 정리에서 `1_2026-2학기_강의자료` 로 바뀌어 대괄호가 없다
   - 남아 있는 대괄호는 볼트 안의 `[2025] ROS2_VRX_Gazebo_Simulink/` 하나뿐이다.
     이 폴더를 다룰 때는 `*ROS2_VRX_Gazebo_Simulink*` 로 우회한다

## 3. 문체 — 개조식 (필수)

> [!important] 모든 문서는 **개조식**으로 쓴다
> 줄글 문단을 쓰지 않는다. 항목으로 끊어서 나열한다.

### 규칙

- 문장을 **명사형 또는 `-함/-임/-음`** 으로 끝낸다
- 한 항목은 **한 줄**. 두 줄이 되면 하위 항목으로 쪼갠다
- 비교·대조·목록은 **표**로 만든다. 줄글로 설명하지 않는다
- 절차는 **번호 목록**. 각 단계는 하나의 동작만
- 강조는 `**굵게**`. 한 문단에 2개를 넘기지 않는다

### 예시

| 이렇게 쓰지 말 것 | 이렇게 쓸 것 |
|---|---|
| "ROS 2는 프로그램을 독립된 노드로 쪼개고 그 사이의 통신을 표준화함으로써 모듈 간 결합을 낮추고 여러 언어를 함께 쓸 수 있게 해 줍니다." | - 프로그램을 독립된 노드로 분리<br>- 노드 간 통신을 표준화<br>- 결과: 모듈 결합 낮아짐, 언어 혼용 가능 |

### 어조 — 정식 교재

> [!important] 1·2인칭과 시점 표현을 쓰지 않는다

| 쓰지 말 것 | 쓸 것 |
|---|---|
| 여러분, 우리 | 학습자, 본 과목 |
| 오늘, 오늘의 | 이번 주차, 본 절 |
| ★ 오늘의 핵심 | (중요), — 핵심 항목 |
| 담당 노트북 실측 | 기준 환경 실측값 |
| 함정, 지뢰, 드디어, 그냥 | 유의 사항, 별도 옵션 없이 |
| "여기서 매년 막힌다" | "매 학기 반복되는 오류" |

- 콜아웃 제목도 **서술형 명사구**로 쓴다 — "왜 위험한가"(×) → "오류 메시지 없이 잘못된 결과가 나온다"(○)
- `~할 것`, `~하지 않는다` 같은 지시형 어미는 교재 어투이므로 그대로 쓴다

### 예외

- 콜아웃(`> [!note]`) 안의 짧은 설명은 서술형 허용
- 지식카드(`20-지식/`)의 `## 한 줄 요약` 은 완결된 한 문장

## 4. 주차 자료 작성 규칙 (`10-주차별-강의자료/`)

`_templates/주차자료.md` 를 복사해서 시작한다. **골격을 바꾸지 않는다.**
학생이 15주 내내 같은 구조를 기대하게 만드는 것이 목적이다.

```
프론트매터
제목 + 과목/이번 주차 학습 내용
[!important] 이 문서를 읽는 방법 / 시작 전 확인
이 주차를 마치면 할 수 있어야 하는 것   (번호 목록)
준비물                                  (표)
--- 1부 이론 ---
1-1, 1-2, ...                          (그림 1~3장 포함)
--- 2부 실습 ---
2-1, 2-2, ...                          (단계별 명령어 + 정상 출력)
--- 마무리 ---
이번 주차 요약                          (표)
수업 진도 체크                          (체크박스, 필수)
과제 N                                  (요구사항 + 평가 배점표)
막혔을 때                               (증상/원인/해결 표)
참고 자료
다음 주 예고
```

### 대상 독자 — 완전 초보자

> [!important] **리눅스 · ROS · 시뮬레이터를 한 번도 안 해 본 학생** 기준으로 쓴다

- 새 용어는 **첫 등장 시 반드시 설명**. 필요하면 "용어 정리" 표를 절로 만듦
- 비유를 쓴다 (`apt` = 앱스토어, 노드 = 직원 한 명)
- **화면에 무엇이 보이는지** 적는다. "이런 화면이 나오면 정상"
- 학생이 당황하는 지점을 미리 적는다
  - 예: "비밀번호를 입력해도 화면에 아무것도 안 보이는 것이 정상임"
- 클릭 경로를 생략하지 않는다
  - 나쁨: "관리자 권한으로 PowerShell 실행"
  - 좋음: "`Win` 키 → `powershell` 입력 → 검색 결과에서 **우클릭** → **관리자 권한으로 실행**"

### 명령어 규칙

- **반드시 복사 가능한 코드블록**. 스크린샷 속 명령어는 오타 공장이다
- 코드블록 하나에 **한 덩어리**만. 길게 이어 붙이지 않는다
- 명령어 뒤에 **정상 출력 예시**를 붙인다

````markdown
```bash
ros2 topic hz /chatter
```

- 정상 출력

```
average rate: 1.000
  min: 0.999s max: 1.001s std dev: 0.00050s window: 10
```
````

- 한 줄로 이어져야 하는 긴 명령어는 `[!warning]` 으로 명시
- 위험한 명령(`rm -rf` 등)은 `[!caution]` 으로 경고

### 수업 진도 체크 (필수)

- 문서 끝, 과제 앞에 반드시 넣는다
- 목적: **학생이 스스로 확인하고 넘어갈 수 있게** 하는 것
- 3~4개 소분류로 나눈다

```markdown
## 수업 진도 체크

> [!important] 다음 주 수업을 따라가기 위한 최소 조건

### 이론 이해
- [ ] ...를 설명할 수 있다

### 실습 완료
- [ ] ... 명령이 성공했다

### 관찰 기록 / 다음 주 준비 / 신고 사항
- [ ] ...
```

- 항목은 **검증 가능한 형태**로 쓴다
  - 나쁨: `- [ ] ROS 2를 이해했다`
  - 좋음: `- [ ] ros2 run demo_nodes_cpp talker / demo_nodes_py listener 통신 성공`

### 과제 규칙

- **평가 배점표를 반드시 붙인다**
- **"검증했는가" 항목이 30% 이상**이어야 한다 → [[측정하지-않은-성공은-성공이-아니다]]
- 검증은 수치로 제출하게 한다. "잘 됐다"는 인정하지 않는다

## 7. 프론트매터

모든 문서 첫머리에 붙인다. 값에 `:` 나 `#` 가 들어가면 `"큰따옴표"` 로 감싼다.

```yaml
---
type: week            # plan | guide | week | knowledge | reference | assignment
week: 3               # type: week 일 때만
title: 3주차 — Gazebo VRX 구축과 좌표계
date: 2026-09-03
tags: [week, gazebo, vrx]
status: done          # draft | done
summary: 한 줄 설명. 마침표 없이
---
```

- `tags` — 소문자 영문, 하이픈 구분. 문서당 2~4개. 본문에 `#태그` 를 뿌리지 않는다
- `summary` — README 표와 Dataview에 그대로 쓰인다. 25자 안팎
- `date` — **오늘 날짜를 실제로 확인해서** 쓴다. 상대 표현("다음 주")을 문서에 남기지 않는다

## 9. 지식카드 (`20-지식/`)

**제목이 곧 주장이다.** `좌표계.md` 가 아니라 `ENU와-NED를-섞으면-조용히-틀린다.md`.
제목만 읽고도 무슨 얘기인지 알아야 한다.

구조는 고정:

```markdown
## 한 줄 요약
> 인용 블록 한 문장

## 무슨 일이 일어나는가
## 왜 중요한가 / 어디에 쓰나
## 연결
```

- **하나의 카드에 하나의 원리.** 둘이면 쪼갠다
- 수업에서 학생이 반복해서 걸려 넘어진 것을 발견하면 카드로 만든다 — 그게 이 폴더의 목적이다

## 11. Simulink 모델 (`10-주차별-강의자료/W0*_simulink/`)

> [!important] 모델은 **손으로 그리지 않는다.** `build_wXX_models.m` 이 전부 만든다
> 학생이 마음껏 만져 보고 `>> build_w07_models` 한 줄로 되돌릴 수 있어야 한다.

### 배치와 색

- 생성 스크립트 끝에서 **`tidy_layout` 을 두 번** 부른다 (한 번은 수렴 안 함)
- 폴더마다 `tidy_layout.m` 사본이 있다. 학생이 `tidy_layout('W07_0_offline')` 로 복구
- 전 모델 상태 점검: `_tools/tidy_all.m` — **겹침 0 이 합격선**

| 색 | 역할 |
|---|---|
| 파랑 | 유도 Guidance |
| 보라 | 미션 판단 (Stateflow, 모드 전환) |
| 주황 | 제어 Control |
| 노랑 | 추진기 |
| 초록 | 운동모델 Plant |
| 분홍 | 외란 (바람·파랑) |
| 연보라 | ROS 통신 · 신호처리 |
| 회색 | 로깅·표시 |
| 흰색 | 설정값 Constant |

- 선은 **직선 또는 직각**만. 대각선 금지
- 되먹임은 **Goto/From 태그**. 화면을 가로지르는 선을 만들지 않는다
- 좌→우 순서: 유도 → 제어 → 추진기 → 운동모델 → 로깅

### VRX 연동 모델

- 실행은 `W0X_vrx_run.m` 한 줄로 한다
  - 토픽 확인 → **RTF 자동 측정** → 페이싱 설정 → 실행 → 결과·대조 그림
  - 손으로 RTF 를 재고 페이싱을 맞추는 절차는 학생이 반드시 틀린다
- VRX 모델에도 `Animate` 블록을 넣는다. 주행 중 항적이 보인다
- **Subscribe 는 첫 메시지 전에 0 으로 채운 버스를 낸다.**
  좌표 변환에 그대로 넣으면 위치가 스폰 원점만큼(약 568 m) 튄다 → `Nav` 첫머리 가드
- 오프라인 ↔ VRX 이격은 **위상 오차인 경우가 많다.** 궤적이 겹치는지 먼저 볼 것

### 모델을 고쳤으면

1. `build_wXX_models` 재실행 (tidy 포함)
2. PNG 재추출 — `print('-s모델','-dpng','-r100', fullfile(pwd,'img','모델.png'))`
3. MD 의 수치를 **다시 측정한 값**으로 갱신
4. PDF 재생성

> [!warning] 문서의 수치는 전부 실행 결과다
> 오차·시간·반경을 추정으로 쓰지 않는다. 구간(전 구간 / 초기 제외)을 반드시 명시한다.

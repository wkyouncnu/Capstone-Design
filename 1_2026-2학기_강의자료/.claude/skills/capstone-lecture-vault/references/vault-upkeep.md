# 볼트 유지

## 1. 폴더의 성격

| 폴더 | 역할 | 학생 배포 |
|---|---|---|
| `00-운영/` | 강의계획서, 평가, 정책 | ✕ — 내부 판단·뒷사정은 전부 여기 |
| `10-주차별-강의자료/` | 주차별 자료 | **○** |
| `20-지식/` | 다음 학기에도 쓸 원리 — 지식카드 | ✕ (쌓인다) |
| `30-환경/` | 설치·환경·워크플로 가이드 | ○ (일부) |
| `40-자산/` | 기존 코드·모델·문헌 인벤토리 | ✕ |
| `50-원본자료/` | 교재·논문·원본 PPT (남이 만든 자료) | ✕ — 고치지 않는다 |
| `80-과제/` | Term Project 명세, 루브릭 | **○** |

> [!important] 배포 폴더에 미확정 계획을 쓰지 않는다
> "아마 이렇게 할 예정", "채점은 상황 봐서" 같은 문장은 `00-운영/` 으로.

`40-자산/` 의 수치·파일명은 **확인한 것만** 쓴다. 추측으로 채우지 않는다.

## 2. 프론트매터

```yaml
---
type: week            # plan | guide | week | knowledge | reference | assignment
week: 3               # type: week 일 때만
title: 3주차 — Gazebo VRX 구축과 좌표계
date: 2026-09-03
tags: [week, gazebo, vrx]
status: done          # draft | done
summary: 한 줄 설명. 마침표 없이
---
```

- 값에 `:` 나 `#` 가 들어가면 `"큰따옴표"`
- `tags` — 소문자 영문, 하이픈. 문서당 2\~4개. 본문에 `#태그` 를 뿌리지 않는다
- `summary` — README 표와 Dataview 에 그대로 쓰인다. 25자 안팎
- `date` — **오늘 날짜를 실제로 확인해서** 쓴다. "다음 주" 같은 상대 표현을 남기지 않는다

## 3. 링크

| 대상 | 형식 |
|---|---|
| 볼트 내 문서 | wikilink `[[파일명]]` — 확장자·경로 없이 |
| 그림 | 표준 마크다운 `![](../assets/x.svg)` |
| 볼트 밖 파일 (PPTX, PDF, `.slx`, 논문) | 경로를 본문에 그대로 — `2_지난학기_강의자료/2025/11_동역학모델.pdf` |

`![[파일명]]` 임베드는 쓰지 않는다. Obsidian 전용이라 VSCode·GitHub 에서 깨진다.

파일명 — 공백은 하이픈(`평가와-팀운영.md`). 주차 자료만 예외로 `W01_...` 형식(정렬 목적).

## 4. 지식카드 (`20-지식/`)

**제목이 곧 주장이다.** `좌표계.md` 가 아니라 `ENU와-NED를-섞으면-조용히-틀린다.md`.

```markdown
## 한 줄 요약
> 인용 블록 한 문장 (완결된 문장 — 개조식 예외)

## 무슨 일이 일어나는가
## 왜 중요한가 / 어디에 쓰나
## 연결
```

- 하나의 카드에 **하나의 원리.** 둘이면 쪼갠다
- **만드는 시점** — 학생이 반복해서 걸려 넘어진 것을 발견했을 때, 또는 작업 중 같은 지뢰를
  두 번 밟았을 때. 그게 이 폴더의 목적이다
- 주차 자료 본문에서 `[[카드이름]]` 으로 걸어 준다. 걸리지 않은 카드는 읽히지 않는다

## 5. 색인 갱신 — 자동 스크립트는 없다

문서를 추가·이동했으면 **손으로** 고친다.

| 고칠 곳 | 무엇 |
|---|---|
| `README.md` | 주차 표 (문서 · 그림 수 · PDF 쪽수 · 주제), 지식카드 목록, assets 목록 |
| `10-주차별-강의자료/README.md` | 주차 표 |
| `00-운영/강의계획서.md` §4 | 주차 블록 |
| 〃 §3.5 · `40-자산/참고문헌.md` | 새 문헌 |
| 〃 §9 | 검증 이력 — **실측 수치를 남기는 곳** |

### 주차 번호를 옮길 때 (파급이 가장 크다)

10주차에 DP 를 넣으면서 뒤가 전부 밀린 사례가 있다. 순서대로 확인한다.

1. `강의계획서.md` §1.3 단계 표 (Phase 구간)
2. 〃 §4 주차 블록 — 옮긴 주차 **앞뒤 주차의 "다음 주 예고"** 까지
3. `README.md` 두 곳의 주차 표
4. 영향받는 주차 MD 의 프론트매터 `week:` 와 제목
5. 각 MD 끝의 **"다음 주 예고"**
6. 병합·삭제한 주차가 있으면 그 사실을 §4 에 한 줄로 남긴다
7. 전부 PDF 재생성

## 6. 끝내기 전

```bash
bash .claude/skills/capstone-lecture-vault/scripts/vault_check.sh
```

- 깨진 wikilink 0 / 없는 그림 0 / MD·PDF 쌍 완비 / 금지 표현 0
- 백업 파일(`*.bak`)을 남기지 않는다
- VRX 를 띄웠으면 프로세스를 정리한다 → `vrx-runbook.md` §6
- 작업 기록은 `~/.claude/plans/` 의 계획 파일 끝에 날짜와 함께 덧붙인다.
  **볼트 문서에 작업 일지를 쓰지 않는다** — 배포본이 지저분해진다

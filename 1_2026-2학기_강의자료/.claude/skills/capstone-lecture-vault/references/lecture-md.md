# 주차 자료를 쓰는 절차

## 1. 골격은 바꾸지 않는다

`_templates/주차자료.md` 를 복사해서 시작한다. 학생이 15주 내내 **같은 자리에서 같은 것을
찾게** 만드는 것이 목적이다. 절을 빼거나 순서를 바꾸지 않는다.

```
프론트매터 → 제목 → 참조 강의 블록 → 이 문서를 읽는 방법 → 학습 목표 → 준비물
1부 이론 (1-1, 1-2, …)  그림 1~3장
2부 실습 (2-1, 2-2, …)  단계별 명령어 + 정상 출력
이번 주차 요약(표) → 수업 진도 체크 → 과제 → 막혔을 때 → 참고 자료 → 다음 주 예고
```

주차별 실제 분량 감각 — PDF 기준 **16\~24쪽**. 6주차 전(Simulink 기초)만 42쪽 이상으로 예외.

> [!important] 완성도 합격선은 `week-quality-bar.md` 에 있다
> 다이어그램 2장 이상 · 정상출력 2건 이상 · 검증된 예제 · 실측 수치 · 막혔을 때 표.
> 주차를 손볼 때는 그 문서의 진단 명령부터 돌린다.

### 참조 강의 블록 (전 주차 공통)

- H1 **바로 다음**에 온다. 원본은 `_templates/참조강의블록.md`
- 담당 교수의 선수 강의 5개(YouTube 재생목록 + Google Drive)와 MATLAB·Simulink Onramp 링크
- **문서마다 고쳐 쓰지 않는다.** 전 주차에서 글자 하나까지 같아야 한다
- 링크가 바뀌면 **원본을 고치고** 전 주차 문서에 다시 심은 뒤 PDF 를 재생성한다
- 확인

```bash
grep -c '참조 강의 — 본 과목이 전제하는 배경' 10-주차별-강의자료/W*.md
```

- 이 블록은 `00-운영/강의계획서.md` 에도 같은 자리에 들어간다

## 2. 대상 독자 — 매번 이 사람을 떠올린다

> 리눅스·ROS·시뮬레이터를 **한 번도 안 해 본** 학부 4학년

| 이렇게 쓰면 실패한다 | 이렇게 쓴다 |
|---|---|
| "관리자 권한으로 PowerShell 실행" | "`Win` 키 → `powershell` 입력 → 검색 결과에서 **우클릭** → **관리자 권한으로 실행**" |
| 용어를 설명 없이 씀 | 첫 등장 시 반드시 설명. 세 개 넘으면 "용어 정리" 표를 절로 만듦 |
| 명령어만 나열 | 명령어 뒤에 **정상 출력 예시**를 붙인다 |
| 학생이 당황할 지점을 방치 | 미리 적는다 — "비밀번호를 입력해도 화면에 아무것도 안 보이는 것이 정상임" |

비유를 쓴다: `apt` = 앱스토어, 노드 = 직원 한 명, 토픽 = 사내 게시판.

### 명령어

- **반드시 복사 가능한 코드블록.** 스크린샷 속 명령어는 오타 공장이다
- 코드블록 하나에 **한 덩어리**만
- 한 줄로 이어져야 하는 긴 명령은 `[!warning]` 으로 명시
- `rm -rf` 등 되돌릴 수 없는 명령은 `[!caution]`

## 3. 문체 — 개조식

- 문장을 **명사형 또는 `-함/-임/-음`** 으로 끝낸다
- 한 항목은 **한 줄**. 두 줄이 되면 하위 항목으로 쪼갠다
- 비교·대조는 **표**. 줄글로 설명하지 않는다
- 절차는 **번호 목록**. 한 단계에 한 동작
- 강조 `**굵게**` 는 한 문단에 2개까지

예외 — 콜아웃 안의 짧은 설명, 지식카드의 `## 한 줄 요약`.

## 5. 수업 진도 체크 (필수)

문서 끝, 과제 앞에 반드시 넣는다. 목적은 **학생이 스스로 확인하고 넘어가는 것**이다.

```markdown
## 수업 진도 체크

> [!important] 다음 주 수업을 따라가기 위한 최소 조건

### 이론 이해
- [ ] ...를 설명할 수 있다

### 실습 완료
- [ ] ... 명령이 성공했다

### 관찰 기록 / 다음 주 준비 / 신고 사항
- [ ] ...
```

항목은 **검증 가능한 형태**로 쓴다.

| 나쁨 | 좋음 |
|---|---|
| `- [ ] ROS 2를 이해했다` | `- [ ] ros2 run demo_nodes_cpp talker / demo_nodes_py listener 통신 성공` |
| `- [ ] 제어기를 만들었다` | `- [ ] 헤딩 스텝응답 정착시간을 초 단위로 기록했다` |

## 6. 과제 — 배점표가 없으면 과제가 아니다

- **평가 배점표를 반드시 붙인다**
- **"검증했는가" 항목이 30% 이상.** 7주차 55%, 10주차 65% 가 실제 사례다
  → [[측정하지-않은-성공은-성공이-아니다]]
- 검증은 **수치로 제출**하게 한다. "잘 됐다" 는 인정하지 않는다
- 좋은 검증 항목의 형태
  - 조건을 **한 번에 하나만** 바꾼 비교표 (게인 3조건, 외란 3조건)
  - 오프라인 ↔ VRX 대조표
  - 이론값과 실측값의 차이 + 그 차이에 대한 5\~10줄 분석

### 범위는 `\~` 로 쓴다 — 그냥 `~` 는 취소선이 된다

- "−90°\~+90°", "10\~20 Hz" 처럼 범위에 쓴 `~` 가 **한 문단에 둘** 있으면, marked(PDF) 와 GitHub 는 그 사이를 **취소선**으로 그린다 (GFM 의 `~글자~`)
- 2026-09-18 7주차 "−90°\~+90° … −180°\~+180°" 가 한 줄 통째로 그어져 있었다. 볼트 전체에 231곳이었다
- 본문에서는 `\~` 로 쓴다. 코드 블록 · `인라인 코드` · 수식 안은 그대로 둔다 (거기서는 취소선이 안 되고, `\~` 는 글자 그대로 보인다)
- 한꺼번에 고치는 도구 — 코드와 수식은 건드리지 않는다

```bash
perl _tools/escape_tilde.pl --check 10-주차별-강의자료/*.md     # 세기만
perl _tools/escape_tilde.pl 10-주차별-강의자료/*.md             # 고친다
```

- `vault_check` 14번이 이것을 센다. 0 이 합격선

| $K$ | Nomoto 이득 | 롤 모멘트 (3주차 표) | 한 줄 주석 | 5주차 F-5 |
| $\mathbf{s}$ | 상태 벡터 | 라플라스 $s$ | 굵기로 구분, 한 줄 주석 | 3주차 1-8 |
| $R$ / $R_{\text{switch}}$ | 수락반경 | 같은 양에 두 표기 | **통일** → $R$ (MSS 원문 $R_{\text{switch}}$ 괄호) | 7주차 |
| $\zeta$, $\omega_n$ | 헤딩 루프 값 | 8주차 식 (27) 표준형 | **바꿨다** → $\zeta_c$, $\omega_c$ | 8주차 |

- **바꿀 수 있으면 바꾼다.** 교과서 표기처럼 이 과목이 고른 것은 바꾼다 ($u \to \tau$, $r \to y_d$)
- **바꿀 수 없으면 경고표.** 논문 기호, 업계 관례, 메시지 필드 이름은 바꾸면 원문과 대조가 안 된다
- 경고표는 **두 번째 뜻이 처음 나오는 곳**에 둔다. 앞 주차로 돌아가 고치지 않는다
- 새 기호를 들이기 전에 이 표에 있는지 본다. 없으면 이 표에 한 줄을 더한다

> [!note] 코드 이름은 이 규칙 밖이다
> MATLAB 변수 `u`, `r` 은 코드 안에서 뜻이 정해져 있으면 된다. 다만 **로그 신호 이름**은
> 학생이 그래프 축에서 읽으므로 이 표를 따른다 — 6주차 PID 모델의 제어입력 신호를 `u` 에서
> `tau` 로 바꾼 이유다.

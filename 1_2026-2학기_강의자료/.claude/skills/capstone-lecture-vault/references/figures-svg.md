## 2. TikZ 파이프라인

```bash
bash _tools/tikz2svg.sh assets/src/w06-control-loop.tex assets/w06-control-loop.svg
```

- 경로 — `latex` → **DVI** → `dvisvgm --no-fonts` → SVG (PNG 도 같이 나온다)
- 스타일은 `assets/src/capstone-style.tex` 하나에서만 정한다. 그림마다 다시 정하지 않는다
- 블록 테두리 색은 **Simulink 모델 색 규칙과 같다** — `gblk` 유도 · `cblk` 제어 ·
  `tblk` 추진기 · `pblk` 운동모델 · `nblk` 항법

> [!caution] 한글은 `latex`(DVI) 경로로만 나온다
> | 경로 | 결과 |

> | XeLaTeX → PDF → dvisvgm | ✕ dvisvgm 이 Ghostscript 10.07 을 거부 |
> | XeLaTeX → XDV → dvisvgm | ✕ TikZ 그래픽이 PDF special 로 빠져 **글자만** 남는다 |
> | **`latex`(ko.TeX) → DVI → dvisvgm** | **○** 그래픽·한글·수식 전부 |
>
> 필요한 TeX 패키지 — `kotex-utf` · `cjk-ko` · `nanumtype1` · **`kotex-plain`**.
> 마지막 하나가 없으면 `I can't find file kotexutf-core` 로 실패한다.
> TinyTeX 은 `%APPDATA%\TinyTeX` 에 있고 PATH 에 없으므로 스크립트가 직접 붙인다.
>
> **새 PC 에 까는 법** (2026-10-16 노트북, 약 3 분) — PowerShell

## 3. 기하 그림은 좌표를 손으로 찍지 않는다

수직·평행·각도가 **뜻을 나르는** 그림(LOS 기하, 좌표계, 벡터 분해)에서는
좌표를 눈대중으로 찍으면 안 된다. 보기에 그럴듯해도 **틀린 그림**이 된다.

> [!warning] 2026-09-17 에 실제로 있었던 일
> 5주차 LOS 그림에서 `y_e` 가 경로에 **수직이 아니었다.** 내적이 $17.9$ 였다
> (수직이면 $0$). 직각 표시도 없어서 아무도 눈치채지 못한 채 PDF 로 나갔다.
> 같은 그림에서 $\pi_p$ 를 **북이 아니라 동에서** 재고 있었고,
> 전환 판정이 쓰는 $x_e$ 는 아예 빠져 있었다.
> 학생이 "수선의 발" 을 경로 밖의 점으로 배우게 되는 그림이었다.

### 방법 — 기준점과 방향벡터에서 계산한다

`.tex` 머리말에 **계산 과정을 주석으로 남긴다.** 나중에 좌표를 고칠 때
무엇이 무엇에서 나왔는지가 그 주석에 있다.

```latex
% pi_p = 50 deg,  x_e = 45, y_e = 18, Delta = 30 (mm) 에서 계산한 값
%     t = (sin 50,  cos 50) = ( 0.76604,  0.64279)    경로 방향
%     n = (cos 50, -sin 50) = ( 0.64279, -0.76604)    경로의 오른쪽
%     F  = wk + 45 t  = (48.47, 42.93)      수선의 발
%     배 = F  + 18 n  = (60.04, 29.14)
%     A  = F  + 30 t  = (71.45, 62.21)      조준점
%     arctan(18/30) = 30.96 deg,  psi_ref = 50 - 30.96 = 19.04 deg
```

### 그리기 전에 수치로 검증한다

```bash
awk 'BEGIN{
  pi=3.14159265358979; d=pi/180; p=50*d;
  tx=sin(p); ty=cos(p); nx=cos(p); ny=-sin(p);
  kx=14; ky=14; xe=45; ye=18; De=30;
  fx=kx+xe*tx; fy=ky+xe*ty;  sx=fx+ye*nx; sy=fy+ye*ny;
  ax=fx+De*tx; ay=fy+De*ty;
  printf "수직성 (0 이어야) = %.6f\n", (fx-sx)*tx+(fy-sy)*ty;
  printf "시선 방위각 = %.2f  기대 %.2f\n", atan2(ax-sx,ay-sy)/d, 50-atan2(ye,De)/d;
}'
```

- **수직성은 내적으로** 잰다. $0$ 이 아니면 그림이 틀린 것이다
- **그려진 화살표의 방향이 정말 그 각인지** 도 잰다. 라벨만 맞고 선이 틀린 경우가 흔하다

### 뜻이 있는 각은 직각 표시를 그린다

- 수직이면 **직각 표시를 반드시 넣는다.** 표시가 없으면 독자는 수직인지 알 수 없고,
  틀렸을 때 아무도 발견하지 못한다
- 방위각은 **어디서 재는지**를 그림 안에 적는다. 본 과목의 $\pi_p$ · $\psi$ 는
  전부 **북에서** 잰다. 북을 가리키는 점선을 같이 그린다

### 회전한 글자는 기호를 망가뜨린다

- `rotate=40` 을 준 `$\Delta$` 는 화면에서 `▷` 로 읽힌다. **기호 라벨은 회전하지 않는다**
- 회전해도 되는 것은 글자 여러 개로 된 이름표(`계획 경로`)뿐이고, 그것도 선에서 떨어뜨린다

---


### 회전 화살표는 양의 방향으로, 그리고 계산으로 확인한다

- 오른손 법칙의 **양의 방향**으로 그린다. 3차원 그림에서는 눈으로 판별이 어렵다 — 곡선의 시작점과 끝점을 그 축에 수직인 평면의 각으로 바꿔서 **각이 늘어나는지** 본다
- 2026-09-18 — 3주차 오일러각 그림에서 **롤 화살표만 반대**(우현이 올라가는 음의 롤)였다. 피치 · 요 화살표는 맞았다. $\mathbf{R}_x(\phi)\,\mathbf{e}_y = (0,\ \cos\phi,\ \sin\phi)$ — 양의 롤에서 $y$ 는 $+z$(아래)로 간다
- 같은 날 5주차 크랩각 그림에서 $\chi$ 호와 $\beta$ 호가 모두 **동쪽**에서 재고 있었다. $\beta$ 는 $\psi$ 선과 $\chi$ 선 **사이**다. 호를 그릴 때는 시작 각을 기준선(북 또는 다른 선)의 TikZ 각으로 적는다

| 확인할 것 | 방법 |
|---|---|
| 호가 어디서 시작하는가 | 방위각은 북 = TikZ 90°. 북에서 시계로 $\alpha$ 는 TikZ $90 - \alpha$ |
| 두 선 **사이**의 각인가 | 호의 시작·끝이 두 선의 TikZ 각과 같은지 계산 |
| 회전 화살표의 방향 | 곡선 점들의 각이 오른손 방향으로 늘어나는지 |
| 블록도 합산점의 부호 | 본문 식과 같은 오차 정의인지 — 9주차 DP 그림은 $\eta_d - \eta$ 를 만들어 본문($\eta - \eta_d$)과 반대였다 |

### 셸로 TikZ 를 고치지 않는다 — 줄바꿈 `\\` 가 깨진다

- 이 환경의 Bash 는 명령 안의 백슬래시 두 개(`\\`)를 하나(`\`)로 줄인다. heredoc · `sed` · `perl` · `awk` 로 넣은 TikZ 줄바꿈 `\\` 가 `\` 하나로 바뀌어 **kotex 가 "Undefined Control Sequence"** 로 멈춘다
- 이 절을 쓸 때도 그렇게 깨졌다 — 셸로 넣은 이 문단의 `\\` 가 전부 `\` 로 바뀌어 있었다
- `awk` 의 문자열 안 `$tmp` 는 필드 참조라 **그 줄 전체**로 바뀐다. `perl` 은 `$변수`를 펼친다
- **백슬래시가 든 줄은 Edit 도구로 고친다.** 새 파일은 Write 도구로 쓴다
- TikZ 노드 글자에 `§` 를 쓰지 않는다 — kotex 가 같은 오류로 멈춘다. `1-8절` 처럼 쓴다

### `shift=` 는 좌표 매크로를 받지 못한다

`\newcommand{\BP}[2]{({#2*20},{#1*20})}` 처럼 괄호까지 포함한 좌표 매크로를 만들어
두면 `\BP{3}{1}` 은 쓸 수 있지만 `[shift={\BP{3}{1}}]` 은 **펼쳐지기 전에 파싱되어**
오류가 난다. `shift` 에는 숫자를 직접 적거나, 매크로를 둘(`\BX`·`\BY`)로 나눈다.

### 극좌표 반지름에는 단위가 따라붙지 않는다

`x=1mm, y=1mm` 를 걸어 둔 그림에서 `(30:48)` 의 48 은 **mm 가 아니라 cm** 로 읽힌다.
호의 반지름은 `({48*1mm})` 처럼 단위를 붙여 적는다.

### 호는 **도형 밖** 반지름에 그린다

돌림을 나타내는 호를 도형 반지름보다 작게 잡으면 도형 안을 지나며 선과 글자를 긁는다.
6주차 추진기 그림은 선체 반폭이 20.5 mm 라 호를 48 mm 에 두었다.

### `border` 는 먹지 않는다 — `--exact-bbox` 가 이긴다

`tikz2svg.sh` 는 `latex` → DVI → `dvisvgm --exact-bbox` 로 간다. `--exact-bbox` 는
**실제 잉크**로 경계를 다시 재므로 `\documentclass[border=12pt]` 를 키워도 결과가
한 픽셀도 바뀌지 않는다. 여백이 없어 글자가 잘린 것처럼 보여도 **잘린 것이 아니다**.
소스는 다른 그림과 같이 `border=6pt` 로 둔다.

### 블록 아래 라벨은 $y \le -6.2$ 에 둔다

블록 높이가 12 mm 인 `capstone-style` 블록은 아래 모서리가 $-6$ 이다. 라벨을
$-6.2$ 보다 위에 두면 테두리에 닿는다.

## 5. 수식

- MD 본문은 LaTeX — `$y_e$`, `$$ ... $$` → `pdf-and-math.md`
- TikZ 안에서도 같은 문법을 쓴다. 본문과 **같은 글꼴**로 나오는 것이 TikZ 의 장점이다
- 기호는 볼드 벡터로 — `$\boldsymbol{\tau}$`, `$\tilde{\boldsymbol{\eta}}$`

### 수식 검증

1. `$$` 개수가 짝수인가, 행 구분자가 `\\` 인가 (`--fig` 가 검사)
2. PDF 를 뽑아 **수식이 조판되었는지** 본다. `$...$` 가 글자 그대로 보이면 실패다
3. 그림의 기호와 본문 표의 기호가 같은가 — 그림은 `\psi`, 본문은 `psi` 처럼 어긋나지 않게

## 8. 결과 그래프 — 궤적에는 **선체와 선수 방향**을 함께 그린다

> [!important] 궤적선만 그린 XY 그래프를 쓰지 않는다
> 궤적선은 **배가 어디로 갔는지**만 말하고 **어디를 향하고 있었는지**는 말하지 않는다.
> USV 는 sway 속도를 가지므로 선수각 $\psi$ 와 대지침로가 **크랩각만큼 다르다.**
> 그 차이가 5\~9주차 유도 절의 주제 그 자체다.

- 궤적을 그리는 **모든 그림**에 선체 실루엣 + 선수 방향선을 얹는다
- 선체 다각형은 **선미 사각형 + 선수 삼각형**. 방향이 한눈에 보인다
- 실루엣 배치는 **호길이 등간격**으로. 시간 등간격으로 하면 느린 구간에 몰린다
- **NED 회전** — 부호를 바꾸면 배가 반대로 돈다. 그림이 거울처럼 보이는 이유는 대개 이것

```
x_n = x0 + x_b cos(psi) - y_b sin(psi)      % 북
y_n = y0 + x_b sin(psi) + y_b cos(psi)      % 동
```

- **크기** — 수백 m 궤적 위의 5 m WAM-V 는 1 픽셀도 안 된다.
  `L = max(0.045 × 축 범위, 실제 전장)` 으로 잡고, 실제 크기로 그렸으면 **제목에 그렇게 적는다**
- 여러 바퀴를 돌면 **마지막 한 바퀴만** 그린다. 흩뿌리면 겹쳐서 읽을 수 없다

### 외란은 화살표로, 성기게

조류·바람이 든 궤적 그래프에는 그 방향을 화살표로 함께 그린다.
휘어진 궤적만으로는 **물이 어느 쪽으로 갔는지** 알 수 없다.

| 규칙 | |
|---|---|
| 개수 | **한 조건당 3개.** 그 이상은 선체 실루엣과 경쟁한다 |
| 위치 | 궤적 **옆**에 비켜서. 위에 놓으면 선체와 겹친다 |
| 색 | 그 조건의 궤적과 같은 색. 어느 궤적의 조류인지 색으로 짝지어진다 |
| 길이 | 세기에 비례. **0 이면 그리지 않는다** (정수 조건에는 화살표가 없어야 맞다) |

> [!caution] 축으로 옮길 때 성분을 뒤집지 않는다
> 궤적 그래프는 **가로가 동($y$), 세로가 북($x$)** 인데 $\beta_c$ 는 **북에서 시계방향**이다.
> ```
> 동 성분 = V_c sin(beta_c)
> 북 성분 = V_c cos(beta_c)
> ```
> 둘을 바꾸면 모든 화살표가 대각선에 대해 뒤집히는데 **그럴듯해 보인다.**
> 코드에 이 두 줄을 주석으로 남긴다.

- polar 그래프도 같다. MATLAB 은 0°를 오른쪽에 놓고 반시계로 세지만 NED 는 북에서 시계방향이다

```matlab
ax = gca;  ax.ThetaZeroLocation = 'top';  ax.ThetaDir = 'clockwise';
```

- 그리는 함수가 창을 둘 이상 열면 **`gcf` 로 저장하지 않는다.** 핸들을 돌려받아 그것을 저장한다

# 문서 검증 — 학생이 첫 줄부터 따라 했을 때 되는가

> [!important] 한 줄로
> **강의자료를 고쳤으면, 그 자료대로 처음부터 기계가 한 번 실행해 본다.** 합격선은 FAIL 0.

강의자료가 썩는 방식은 하나다 — 명령이 "예전에는 됐던" 상태로 남는 것. 사람이 눈으로 읽어서는
못 잡는다. 실행해야 잡힌다.

---

## 1. 언제 돌리는가

| 시점 | 이유 |
|---|---|
| 주차 자료를 **고친 직후** | 방금 바꾼 명령이 진짜 되는지 |
| **강의 전날** | 그동안 환경이 바뀌었을 수 있다 |
| 패키지 저장소를 **푸시한 뒤** | 학생이 받는 것과 문서가 어긋나지 않는지 |
| ROS·Ubuntu·VS Code 를 **업데이트한 뒤** | 출력 문구가 바뀌는 일이 잦다 |

```bash
wsl -d Ubuntu-22.04 -u <사용자> -- bash -lc \
  "export DISPLAY=:0; bash /mnt/c/<볼트경로>/_tools/verify_w02.sh"
```

- 주차마다 `verify_wNN.sh` 를 만든다. W02 것을 복사해 고치는 것이 빠르다

## 2. 무엇을 검사하는가

문서의 **절 순서 그대로** 간다. 학생이 겪는 순서와 같아야 의미가 있다.

| 절 | 검사 |
|---|---|
| 설치 | `which ros2` · `ROS_DISTRO` · `.bashrc` 자동 적용 · `ros2 doctor` |
| 편집기 | WSL interop · `which code` · `/mnt/c` 접근 |
| 첫 통신 | talker/listener 로그 · `node list` · `topic hz` · `info --verbose` |
| turtlesim | 노드·토픽·서비스·액션·파라미터 목록 + **실제 호출** |
| 저장소 | GitHub 에서 `git clone` → `colcon build` → `pkg executables` |
| 내 노드 | 발행·수신 로그 · 주기 |
| QoS | 정상 수신 → 일부러 어긋냄 → **경고 확인 + 수신 0건** |

## 3. 검사식 쓰는 법

```bash
expect "이름" "기대문자열" 명령...
```

- 출력에 **기대 문자열이 들어 있으면 통과**. 정확히 같을 필요는 없다
- 타임스탬프·경로처럼 매번 달라지는 부분을 피해서 고른다

> [!caution] 기대 문자열이 **다른 문장에도 들어 있지 않은지** 확인한다
> 실제로 겪은 것 — QoS 불일치에서 수신 0건을 확인하려고 `grep -c received` 를 썼다.
> 그런데 경고 문구가 `No messages will be **received** from it` 이라 **1건**으로 세어졌다.
> 문서는 맞는데 **검사식이 틀려서** FAIL 이 났다.
>
> ```bash
> #  나쁨 — 경고 문구까지 센다
> grep -c "received" log
> #  좋음 — INFO 줄만 센다
> grep -c '\[INFO\].*received:' log
> ```

- FAIL 이 나면 **문서가 틀렸는지 검사식이 틀렸는지 먼저 가른다.** 순서를 바꾸면 문서를 망친다

## 4. 스크립트를 쓸 때 이미 밟은 지뢰

| 증상 | 원인 | 조치 |
|---|---|---|
| 스크립트가 첫 줄에서 조용히 끝남 | `set -u` + ROS `setup.bash` (미설정 변수 참조) | **`set +u`** 를 쓴다 |
| `pkill -f '[r]qt'` 가 **자기 셸**을 죽임 | 자기 명령줄에 `rqt` 문자열이 들어 있다 | 정리 명령을 **별도 호출**로 분리 |
| 죽은 노드가 `ros2 node list` 에 계속 보임 | ROS 2 데몬 캐시 | `ros2 daemon stop` 후 재실행 |
| `wsl.exe ... bash -lc '...$VAR...'` 에서 변수가 빈 값 | 바깥 셸이 먼저 확장 | **스크립트 파일로 만들어** 호출 |
| GUI 검사가 항상 실패 | `DISPLAY` 미설정 | 호출 시 `export DISPLAY=:0` |
| 노드가 곧 죽음 | `wsl.exe` 종료 시 자식 정리 | `setsid nohup ... &` 로 분리 |

---

## 5. 결과를 어디에 남기는가

- 통과했으면 **주차 자료 표**(`week-quality-bar.md` §6)에 검증 날짜를 적는다
- FAIL 이 났고 문서가 틀린 것이면 **문서를 고치고 다시 돌린다.** 검사식을 느슨하게 만들지 않는다

```
PASS 35  /  FAIL 0  /  SKIP 0
==> 문서대로 하면 된다 (합격)
```

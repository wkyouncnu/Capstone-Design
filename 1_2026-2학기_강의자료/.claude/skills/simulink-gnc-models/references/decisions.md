# 교수 지시 연대기 — 바뀐 규칙과 그 이유

## 4-1. 교수 지시 2026-10-02 — 합산점 · 자동 정지 · Scope · 서브시스템

### 합산점 부호 목록 — **2026-10-14 부터 언제나 `|+-`**

```matlab
add_sum(s, 'SumU', '|+-', [250 110]);    % 막대를 붙인다. 안 붙여도 add_sum 이 붙인다
```

교수 지시 2026-10-14 — *"시뮬링크 sum 블락은 항상 `|+-` 이런 부호 목록만 사용하도록"*.
`add_sum` 은 들어온 막대를 떼고 **맨 앞에 하나만** 다시 붙이므로, 옛 차수 빌더가
`'+-'` 를 넘겨도 같은 모양이 나온다.

| `Inputs` | 입력 1 | 입력 2 | 출력 | 쓰는가 |
|---|---|---|---|---|
| `'+-'` | 위 | 아래 | 오른쪽 | 아니오 (2026-10-02 ~ 10-14 에 썼다) |
| `'\|+-'` | **왼쪽** | **아래** | 오른쪽 | **예** |

20 x 20 둥근 Sum 을 중심 (200,200) 에 놓고 `PortConnectivity` 로 실측한 값이다 —
입력 1 (185,200) · 입력 2 (200,215) · 출력 (215,200).

**왜 이 모양인가.** 지령이 **왼쪽에서 직선으로** 들어오고 되먹임만 **아래에서**
올라온다. 블록도를 왼쪽에서 오른쪽으로 읽는 규칙 0 과 모양이 같다. `'+-'` 는
지령까지 위에서 꺾여 들어와 "무엇이 지령이고 무엇이 되먹임인가" 가 그림에서
사라진다.

> [!warning] 부호 목록을 바꾸면 **배치가 따라온다**
> 합산점 주변 블록의 **세로 중심을 합산점 중심과 같게** 둔다. 그래야 지령선이
> 꺾이지 않는다. 되먹임은 `feed_from(…, dy)` 의 `dy` 를 0~10 으로 줘 포트 바로
> 옆에서 올린다. 옛 좌표 그대로 다시 빌드하면 `check_lines` 의 「겹침」과
> 「블록관통」이 되살아난다.
### `StopTime` 을 `inf` 로 두지 않는다 — 끝나면 스스로 멈춘다

- `inf` 면 학생이 Stop 을 손으로 눌러야 하고, 언제 눌러야 하는지 알 수 없다.
  Gazebo 가 안 떠 있으면 **빈 화면인 채로 영원히** 돈다
- `AutoStop` 상자가 "오차가 띠 안에서 `settle_hold` 초를 버텼는가" 를 보고
  `Stop Simulation` 을 누른다. `StopTime = T_run` 은 뒤를 받치는 안전장치다
- 버틴 시간은 **연속 적분기**로 센다 (입력 1, 외부 리셋 = 띠 밖). Memory 나
  Unit Delay 가 필요 없어 "전부 연속" 규칙을 깨지 않는다

> [!caution] 외부 리셋은 `level` 이지 `rising` 이 아니다
> `rising` 은 리셋 신호가 0 에서 1 로 **올라가는 순간**만 리셋한다. 실행
> 시작부터 오차가 띠 밖이면 그 신호는 처음부터 1 이라 올라가는 모서리가 없고,
> 리셋이 영영 안 걸려 적분기는 그냥 경과 시간을 센다. 2026-10-02 에 이것 때문에
> 내부루프가 속도 1.03 m/s 인 5.05 s 에 멈췄다.

> [!tip] 띠는 **남는 오차보다 넓게** 잡는다
> 적분 이득이 작으면 정상상태 오차가 오래 남는다. 4주차 속도 루프는 40 s
> 시점에도 0.077 m/s 가 남아, 띠를 0.05 로 잡으면 영영 "자리를 잡았다" 가
> 되지 않고 늘 `T_run` 까지 간다. 실측한 잔류 오차를 보고 띠를 정한다.

### Scope 는 모델 하나에 **한 개**

- 지령과 실제값을 **한 칸에 겹쳐** 놓고, 칸을 세로로 쌓아 **같은 시간축**에 건다
- 창을 둘 띄우면 눈이 왕복해야 하고 시간축을 맞춰 보기 어렵다
- **궤적은 Scope 에 넣지 않는다.** x-y 평면이라 시간축과 축이 다르고,
  실시간 화면(`W0X_animate`)의 왼쪽 큰 칸이 이미 그 일을 한다

### 제어기는 루프마다 **서브시스템 하나**

- 한쪽만 상자이고 다른 쪽은 블록이 흩어져 있으면 제어기가 몇 개인지 셀 수 없다
- 4주차는 `HeadingCtrl` 과 `SpeedCtrl` 두 상자가 `Alloc` 하나로 모인다

### 실시간 화면에 `v` · `r` 은 그리지 않는다

- 단위가 m/s · deg/s · N 으로 자릿수가 달라 축을 둘로 나눠야 했고, 그래도
  `v` 는 거의 0 인 직선이라 읽을 것이 없었다
- 요각속도가 궁금하면 선수각 칸의 **기울기**가 그것이고, 숫자가 필요하면
  `out.log.r` 을 본다

### `check_discrete` 는 PID 블록을 **`SubSystem`** 으로 찾는다

- PID Controller 는 마스크 씌운 서브시스템이라 `BlockType` 이
  `'PID Controller'` 가 아니라 `'SubSystem'` 이다. 그 이름으로 찾으면
  **하나도 안 걸린다**
- 2026-10-02 이전에는 이 때문에 4주차의 이산 PI 두 개(`PI_u`, Ts = 0.05)를
  "이산 0" 으로 잘못 보고했다. 지금은 `TimeDomain` 파라미터가 있는 블록을
  PID 블록으로 본다

## 4-2. 교수 지시 2026-10-14 — ssa 는 합산점 하나 + `Fcn` 하나, Scope 는 범례를 항상

### 각도 오차는 **MATLAB Function 이 아니라** 합산점 + `Fcn`

```matlab
add_ssa(ss, 'ErrPsi', 'Ssa', [230 80]);   % 합산점 '+-' 하나 + Fcn 하나
```

- 그려지는 모양은 이렇다

  ```
  psi_ref --(+)
              >--> [ atan2(sin(u), cos(u)) ] --> e
  psi -----(-)
  ```

- 전에는 이 자리에 MATLAB Function 블록 하나가 있었고 그 안에서 **빼기와 접기를
  함께** 했다. 돌아가기는 하지만 **도면에서 뺄셈이 사라진다** — 되먹임 제어
  그림에서 가장 먼저 찾는 곳이 합산점인데 그것이 상자 안에 숨는다
- 빼기를 밖으로 꺼내면 남는 일은 **접기 하나**뿐이고, 식 한 줄은 `Fcn` 이면 족하다.
  `Fcn` 은 식이 블록 위에 그대로 보여서 열어 볼 필요가 없다
- **값은 그대로다.** 같은 식을 같은 배정밀도로 센다. 4주차 `W04_3_heading` 의
  `HeadingCtrl` 이 본보기이고, 5주차는 2026-10-14 에 이 모양으로 바꿨다

> [!tip] 바꾼 뒤에는 **같은 숫자가 나오는지 재서 보인다**
> 고치기 전 빌더를 `git show HEAD:...` 로 되살려 빌드·실행하고, 고친 빌더로
> 다시 빌드·실행해서 로그 배열을 **비트 단위로** 맞춰 본다. 5주차는 기록 신호
> 17개 × 4330 샘플이 전부 같았다 (`max|차| = 0`). "같을 것이다" 로 끝내지 않는다

### Scope 에는 **범례를 항상** 켠다 — `scope_legend`

```matlab
scope_legend(m);          % 선을 다 놓은 **뒤**에 부른다
```

- 칸 하나에 선이 둘 이상이면 어느 선이 지령이고 어느 선이 실제값인지 알 수 없다.
  `set_param(scope,'ShowLegends','on')` 하나로 끝나는 일이다
- 범례에 찍히는 글자는 **신호 이름**이다. 선에 이름이 없으면 `Signal 1` 로 나오므로
  **켜는 것만으로는 부족하다** — 들어가는 선에 이름이 있어야 한다
- `scope_legend` 가 `Mux` 안쪽까지 따라 들어가고, `From` 으로 온 선은 `GotoTag` 에서
  이름을 가져온다. 다만 **블록 이름을 신호 이름으로 지어내지는 않는다** (`R2D` 가
  범례에 찍히면 범례가 거짓말을 한다). 그런 선은 빌더가 직접 이름을 붙인다

> [!caution] 순서가 뒤바뀌면 범례가 `Signal 1` 로 나온다
> 선을 다시 그으면 이름이 **날아간다**. 그래서 `scope_legend` 는 배선·정리가
> 전부 끝난 **맨 마지막**이다. `tidy_model` 을 쓰는 주차는 그것이 9번째 단계로
> 안에서 부른다. **`tidy_model` 을 거치지 않고 손으로 정리하는 모델은 빌더가
> 직접 불러야 한다** — 5주차의 큰 모델 둘이 그랬고, 그래서 범례가 없었다

## 4-3. 교수 지시 2026-10-14 — 예제는 **사다리**로, 빌더는 **모듈**로

### 쉬운 예제부터 하나씩 쌓는다 (완성품을 통째로 주지 않는다)

교수 지시 — *"아주 간단한 예제부터 복잡한 예제까지 하나하나 개발해서 쌓을 수
있도록"*, *"너무 한꺼번에 완성된 예제를 넣지 말고 시뮬링크 파일을 간단한
예제부터 하나씩 쌓아서"*.

- 한 단계에 **새로 생기는 것은 하나**다. 두 가지를 한꺼번에 더하지 않는다
- 1단은 블록이 **열 몇 개**다. 상수 세 개로 목표 `(x, y, ψ)` 를 주고 거기로 간다
- 단계마다 **그 단계의 `.slx` 하나**를 남긴다. 다음 단계가 앞 단계를 덮어쓰지 않는다
- 각 모델의 왼쪽 위 주석에 **"이번에 새로 생긴 것"** 한 줄을 적는다
- 번호를 파일 이름에 넣는다 — `W06_1_point` · `W06_2_sway` · `W06_3_thrust` …

| 단계 | 새로 생기는 것 | 왜 여기서 |
|---|---|---|
| 1 | 목표 상수 + 위치 P + 속도 PI + 선수각 P-D + 추력 배분 | 제어 고리의 뼈대 |
| 2 | 선수추진기 on/off 게인 | 끄고 켜 보면 횡이동이 왜 되는지 보인다 |
| 3 | 추진기 동역학 (추력↔회전수, 1차 지연, 포화) | 지령과 실제 추력의 차이 |
| 4 | 도착 판정과 정지 게이트 | 멈추는 법 |
| 5 | 단계 전이(접근 → 정렬 → 접안) | 유도가 상태를 가진다 |
| 6 | 시뮬레이터 연동 | 운동모델만 실물로 바뀐다 |

> [!important] 앞 단계에서 생긴 **스위치는 윗단에도 그대로 붙어 있어야 한다**
> 2단에서 생긴 `bow_on` 게인이 3단 이상에서 빠져 있으면, 강의노트가 "`bow_on = 0`
> 으로 두고 돌려 보라" 고 적은 실습이 **그 모델에서는 되지 않는다.**
> 사다리는 *더하기만* 한다 — 윗단에서 빼는 것은 없다.
> 2026-10-15 에 `bow_on`(2단)·`dock_on`(5단) 두 스위치를 3~8단 전체에 다시 붙였다.
> 점검법 — 강의노트가 이름을 적은 스위치를 전부 모아, 그 이름이 그 단계 이상의
> 모든 `.slx` 에 실제로 있는지 `find_system` 으로 센다. **강의자료가 적은 스위치는
> 모델에 있어야 한다.**

### 예제마다 `.slx` 와 **그것을 돌리는 `.m`** 을 한 짝으로

교수 지시 — *"각각 시뮬링크와 m 파일로 개발해줘. m 파일은 최대한 간략하게
자체 함수 만들지 말고"* (2026-10-14), 그리고 그 뜻을 바로잡은
*"m 파일은 시뮬링크를 돌리고 그래프를 그리기 위한 용도다"* (2026-10-15).

- `.m` 은 **물리를 다시 짜지 않는다.** 같은 운동모델을 MATLAB 으로 한 벌 더
  쓰는 것은 틀린 이해였다 — 2026-10-15 에 그렇게 만든 일곱 파일을 지웠다
- 한 단계에 실행 파일 한 장. 하는 일은 세 걸음뿐이다

  ```matlab
  setappdata(0, 'WXX_stage', N);
  setappdata(0, 'WXX_skip_run', true);   % 설정만 받아 온다 — 실행은 이 파일이 한다
  WXX_setup
  load_system(mdl);  out = sim(mdl);
  S = WXX_plot(out, 제목);
  ```

- 그 뒤에 **그 단계에서 봐야 할 숫자만** `fprintf` 로 찍는다. 목표와 끝 자세,
  한계 대비 추력, 단계 전이 시각 같은 것이다. 문서에는 **잰 값만** 싣는다
- `.m` 은 **로컬 함수를 만들지 않는다.** 위에서 아래로 읽히는 스크립트 한 장이다.
  여러 단계를 도는 비교·측정 파일만 **함수**로 둔다 — `WXX_setup` 이 첫 줄에서
  base 를 비우므로 스크립트로 두면 루프 변수가 함께 지워진다
- 모델을 Simulink 에서 직접 Run 해도 같은 실시간 그림이 떠야 한다. 그러려면
  `WXX_setup` 을 한 번 돌려 변수를 base 에 올려 둔 뒤여야 한다

### 빌더는 **한 파일에 한 책임**

교수 지시 — *"시뮬링크 작성하는 스킬도 가능하면 모듈화해줘. 최대한 가독성 높게"*.

```
W06_simulink/
  build_w06_models.m      드라이버 — 단계 목록과 공통 마무리만 (100행 안쪽)
  parts/
    addGuidanceConst.m    단계 1·2·3 의 유도 (상수 세 개)
    addGuidanceStop.m     단계 4 의 유도 (+ 도착 판정)
    addGuidance.m         단계 5 이상의 유도 (단계 전이)
    addOuterLoop.m  addInnerLoop.m  addThrusters.m  addMotionModel.m
    addBoxes.m            Animate · Logging · Scope · AutoStop
    wireFront.m  wireGotos.m
```

- 한 파일이 화면 한두 개를 넘지 않게 한다. 넘으면 쪼갤 자리가 있다는 뜻이다
- 공통 한 줄 헬퍼는 `_tools/` 로 올린다 — `sl_const` · `sl_gain` · `sl_sat` ·
  `sl_pid` · `sl_note` · `sl_fcn` · `sl_fresh`. 주차마다 같은 것을 다시 쓰지 않는다
- 드라이버는 **무엇을 만드는지**만 보이게 한다. 블록 좌표는 `parts/` 안에 둔다

## 4-4. 교수 지시 2026-10-15 — 직선 · 열 정렬 · 전수 검사

교수 지시 세 줄이 같은 날 왔다.

1. *"모든 선들은 가능하면 구부러지지 않고 직선으로."*
2. *"from goto 시뮬링크 블락들에 연결된 선들도 가능하면 다 직선으로. 굽히지 말고."*
3. *"이런 식으로 내가 직접 정렬한 거다. 가능하면 위치도 통일해서, 선들도 직선으로
   하고, 가로 세로도 정렬 되도록."* — W06_1_point 을 손수 정렬한 도면과 함께

### 무엇이 바뀌었나

| 바뀐 것 | 어디에 |

| 합산점을 **전수로** 보는 `check_sums` 가 생겼다 | `checks.md` 「합산점 검사」 |

### 전수로 재지 않으면 못 찾는 것

- 합산점 **112 개**가 막대 없이 저장되어 있었다. `add_sum` 은 붙이고 `mss_style` 이
  떼고 있었다. 한 모델만 열어 보아서는 알 수 없다
- 태그 선이 **거의 다 1 회씩 꺾여** 있었다. `snug_tags` 가 "오른쪽으로 더 가는 선이
  있는가" 를 셀 때 **옮기려는 태그 자신**을 세고 있었기 때문이다. 한 줄이 71 모델에
  퍼져 있었다

**규칙.** 도구를 고쳤으면 **그 도구가 닿는 모델 전부를 다시 재고** 그 표를 남긴다.
한 모델이 좋아진 것은 증거가 아니다.

### 직선율을 올리는 순서

1. `snug_tags` 로 태그를 제 자리에 — 태그 선은 **100% 직선**이 된다
2. 남은 2회는 `check_straight(m, true)` 로 이름을 뽑아 하나씩 본다
3. 포트 높이가 맞출 수 있는 자리면 `align_to`·`fit_span` 으로 맞춘다
4. Mux 모아들이기 · 한 출처에서 갈라짐 · 입력 둘인 Scope · 포트 세 개로 모이는
   추력 배분은 **맞출 수 없다.** 2회가 답이다. 교수가 손수 정렬한 도면에서도
   `OuterLoop -> InnerLoop` 는 꺾여 있다
5. 꺾임 수를 줄이자고 **일곱 항목을 깨지 않는다** (`line-routing.md` §3.2 의 경고)

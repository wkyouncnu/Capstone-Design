## 2. 모델을 만들 때

**`references/build-models.md`** 에 관용구가 전부 있다 — `fresh`/`setFcn`/`C`/`F`/`G`/`note`
헬퍼, Stateflow 프로그래밍 API, 대수 루프 끊는 법, 실시간 페이싱.

절대 규칙 다섯 가지만 여기 적는다.

1. **GNC 순서를 왼쪽에서 오른쪽으로** — 유도 → 제어 → 추진기 → 운동모델 → 로깅.

4. **최상위는 역할별 서브시스템만** — 블록 20개가 넘으면 묶는다. 로깅·그림은 포트 없는 서브시스템으로.
   관용구·색 이름표·지뢰는 **`references/subsystems.md`**

### 제어기·태그·로깅 — 교수 지시 2026-10-01

> *"제어기는 연속으로. 0 인 게인은 지운다. 되먹임 게인은 양수로.
> Goto/From 이 너무 복잡하다. To Workspace 도 너무 복잡하다."*

여덟 줄이다. 넷은 **세는 도구**가 있다
(`check_tags` 0 · `check_discrete` 0 · `check_fill` 참고값 · `check_gains` 참고값).

1. **제어기·전달함수·적분기·미분기는 연속 시간으로 만든다.** 원칙은 **전부 연속**이다
   (교수 지시 2026-10-01 — *"이산 시간 제어기든 전달함수든 전부 연속 시간으로 바꿀 것"*).
   - 적분기는 `simulink/Continuous/Integrator`, 전달함수는 `simulink/Continuous/Transfer Fcn`,
     PID 블록은 `TimeDomain` 을 `Continuous-time` 으로. 솔버는 고정스텝 연속 **`ode4`**
   - 바꿀 것 — `Discrete Transfer Fcn` · `Discrete-Time Integrator` · `Discrete Derivative` ·
     `Discrete Filter` · `Discrete PID` · `Digital Clock` · $\text{num}(z)/\text{den}(z)$ 꼴 전부
   - **시상수·게인·한계값은 그대로 둔다.** 같은 법칙의 **구현만** 바꾸는 것이다
   - **예외는 셋뿐이다** — 대수 루프를 끊는 `Unit Delay`, Stateflow 차트의 이산 샘플,
     ROS `Subscribe`·`Publish`. 예외는 그 블록의 `Description` 에 **왜 이산인지 한 줄**을
     적고 문서에도 한 줄 남긴다. 그러면 `check_discrete` 가 예외로 세어 빼 준다
   - 솔버가 `FixedStepDiscrete` 라는 것은 이유가 **아니다.** `ode4` 로 바꾸면 같은 스텝으로
     돈다. 2026-10-01 에 4주차 VRX 모델이 그랬다 — "VRX 라서 이산" 이라고 2주 동안 적혀
     있었는데 솔버 한 줄의 문제였다. ROS `Subscribe`·`Publish` 는 major step 에서만 돌므로
     토픽 주기도 페이싱도 달라지지 않는다 (5\~9주차 VRX 모델 네 개 `update` 통과로 확인)

   ```matlab
   check_discrete(모델, true)   % 고쳐야 할 이산 블록. **0 이 합격선**
   ```

   **적분기는 대수 루프도 끊는다.** 적분기 출력은 직접 전달이 아니므로, 상태를 함수에
   되먹여도 루프가 생기지 않는다. `MATLAB Function` + `Unit Delay` 로 적던
   `s[k+1] = s[k] + Ts*rate` 는 **함수가 변화율만 내고 적분기가 적분하는** 꼴로 바꾼다
   (2026-10-01 9주차의 상태 다섯 개 — 레퍼런스 모델 · 파랑 필터 · DP 적분항 · 추력 지연 ·
   방위 서보 — 가 전부 이렇게 바뀌어 이산 블록이 **0** 이 되었다). 변화율 태그는 `d_<상태>`
   로 적어 도면에서 적분 전이라는 것이 읽히게 한다.

   **못 바꾸는 블록이 있다** — 연속 `Transfer Fcn` 은 **벡터 입력을 받지 않는다.**
   좌·우 두 축을 함께 보내는 신호(5\~8주차의 `MotorLag` 입력 `n`)에는 쓸 수 없으므로
   `State-Space` 한 블록으로 적는다 ($A = -I/\tau$, $B = I/\tau$, $C = I$, $D = 0$ 이 곧
   1차 지연이고, 대각이라 축이 섞이지 않는다). `Sum`+`Gain`+`Integrator` 로 펼치는 방법도
   있지만 되먹임 선이 생겨 `arrangeSystem` 이 블록을 겹쳐 놓는다 (2026-10-01 에 재현).

2. **게인이 0 인 갈래는 모델에 두지 않는다.** 게인·적분기·합산 입력을 통째로 뺀다
   - **예외 — 문서가 그 갈래를 켜는 실습을 하고 있으면 그대로 둔다.**
     그때는 "어느 절이 켜는가" 를 답할 수 있어야 한다.
     4주차의 0 인 게인 다섯은 전부 이 예외다 —
     `Ki_psi`(2-10 절) · `Kd_u`(2-3 절) · `PID` 블록의 I·D(1-6\~1-9 절)
   - `check_gains` 는 세기만 하고 합격선을 두지 않는다. 도구가 사람 대신
     판단하게 두면 실습이 조용히 사라진다

3. **되먹임 게인은 양수로 두고, 부호는 합산점에서 준다.**
   `Kd_psi = +400` 에 `SumPD` 를 `'+-'` 로. `Kd_psi = -400` 에 `'++'` 가 아니다
   - 게인에 마이너스를 숨기면 **도면만 보고는 덧셈인지 뺄셈인지 알 수 없다**
   - 브레이크인 것은 게인 숫자가 아니라 도면의 그 부호가 말한다. 게인은 세기만 말한다
   - `check_gains` 가 음수 게인을 센다
   - **2026-10-01 에 5\~8주차에도 적용했다.** `Kd_rate` 의 게인이 `-Kd_psi` 였고 `SumN` 이
     `'++'` 였다 → 게인을 `Kd_psi` 로, `SumN` 을 `'+-'` 로. 세 주차 여섯 모델 모두

3-1. **헤딩의 D 항은 요각속도 되먹임 하나로 통일한다** (교수 지시 2026-10-01)

   $$\tau_N = K_{p,\psi}\,\operatorname{ssa}(\psi_{\text{ref}} - \psi) \;-\; K_{d,\psi}\,r$$

   - 오차를 미분하는 갈래(`dedt`, `Discrete Derivative`)와 둘 중 하나를 고르는
     스위치(`DM`/`d_mode`/`Dsel`)는 **두지 않는다.** 그 비교는 4주차 2-8절
     (`W04_heading_sign`) 에서 끝났다 — 같은 설명을 주차마다 반복하지 않는다
   - 스위치가 남아 있으면 **도면만 보고는 어느 쪽이 도는지 알 수 없다.** 설정 파일의
     변수 하나가 도면의 뜻을 바꾸는 구조는 읽는 사람에게 숙제를 넘기는 것이다
   - 지령이 계단으로 바뀌어도 $r$ 은 튀지 않는다. 그것이 이 방식을 쓰는 이유다

3-2. **Gain 블록은 식이 보이게 키운다.** `-K-` 로 숨으면 학생이 어느 게인인지 알 수 없다
   (교수 지시 2026-10-01). MSS 치수보다 **가독성이 먼저**인 예외다
   - Simulink 는 식이 블록보다 넓으면 식을 숨기고 `-K-` 를 그린다. `mss_style` 이
     Gain 을 MSS 치수 `50x36` 으로 일괄 축소하고 있었으므로 `Kp_psi` 같은 이름이 전부
     `-K-` 로 보였다 (5\~8주차 여섯 모델에서 모델마다 2개)
   - `mss_style` 이 Gain 만 예외로 두고 **식 길이에 맞춰 폭**을 잡는다 — 글자당 7 px,
     좌우 여백 16 px, 최소 폭은 MSS 의 50 px. 숫자 게인(`2`·`0.5`)은 그대로다
   - 중심을 보존하므로 **배선이 틀어지지 않는다.** 키운 뒤 일곱 항목(특히 블록겹침·
     이름표위선)과 흐름 검사가 0 인지 확인한다
   - 확인은 눈으로 한다 — 도면 PNG 를 열어 `Kp_psi`·`Kd_rate`·`Ki_psi` 가 실제로 보이는지

4. **Goto/From 태그 이름은 상태 변수 이름 그대로** — `u` `v` `r` `x_n` `y_n` `psi`
   `psi_ref` `u_ref` `X` `N` `FL` `FR`. 블록 이름에서 딴 태그(`MotionModel_1` ·
   `Quat2Yaw_2` · `Integ_1`)와 접미사 태그(`psi_1` · `u_ref_1_1`)는 **금지**
   - **한 신호에 태그 하나.** 그 태그를 여러 From 이 받는다
   - 태그 이름은 **선 이름**에서 온다 — 빌더에서 `set_param(h, 'Name', 'psi')`.
     이름을 안 주면 `tag_feedback` 이 마지막 수단으로 블록 이름을 쓴다
   - `check_tags` 가 셋 다 센다. **0 이 합격선**

5. **태그를 최대한 줄인다.** 이 순서로 판단한다
   1. **가까우면 선으로 잇는다** — 옆 단계로 가는 본선에 태그를 쓰지 않는다
   2. 태그는 **뒤로 돌아가는 신호**(되먹임)와 **멀리 떨어진 상자**(로깅·화면)에만
   3. 화면·로깅이 태그를 늘리는 주범이면 **`Mux`·`Bus` 하나로 묶어** 태그 한 개로
      보내고 받는 쪽에서 푼다. 묶는 **순서 계약표**를 빌더와 받는 함수 양쪽에 적는다
   4. 선으로 되돌렸더니 화면을 가로지르거나 세 번 꺾이면 **그 신호는 태그로 남긴다** —
      그 판단 근거를 주석 한 줄로 남긴다

6. **태그는 신호 바로 옆에 둔다** (교수 지시 2026-10-01 — *"Goto 부분은 실제 신호에
   최대한 가까이 모아 주고, 선들도 꺾이는 부분을 최소화해서 해 줄 것"*)
   - **Goto 는 출발 포트 옆**(같은 높이, 한 칸 오른쪽), **From 은 도착 포트 옆**
     (같은 높이, 한 칸 왼쪽). 그러면 잇는 선이 **수평 한 토막, 꺾임 0회**다
   - 멀리 두면 선이 길어지고 꺾인다. 자리는 손으로 주지 않고 `drop_tag` · `feed_from`
     에 맡긴다 — `spot_free` 로 포트 옆을 먼저 재 보고, 그 자리가 본선 위이거나
     차 있을 때만 `DY` 쪽으로 비킨다
   - **From 블록 이름은 `Fr_<태그>`**. 같은 태그를 여러 곳에서 받으면 **번호만**
     붙인다 (`Fr_psi` · `Fr_psi_2`). `Fr_psi_HeadingCtrl` · `Fr_log_psi` · `FrB_y` ·
     `From_okL` 처럼 **블록 이름을 섞지 않는다** (`_tools/from_name.m`)
   - `lay_sinks` 는 Goto 를 종착 블록으로 세지 않는다. 배치 도구가 태그를 끌고 갔으면
     `snug_tags` 가 다시 포트 옆으로 끌어온다 (`tidy_model` 이 자동으로 부른다)

7. **빈 공간을 남기지 않는다** (교수 지시 2026-10-01 — *"블록을 띄엄띄엄 놓지 말고
   가까이 모아 주세요. 빈 공간이 너무 많습니다."*)
   - 사슬은 **왼쪽 위에서 시작한다** — `lay_chain` 의 `'X0'`·`'Row'` 기본값을 260·400 에서
     **40·40** 으로 내렸다. 왼쪽과 위에 여백을 두면 그만큼 도면이 커진다
   - 단계 간격은 **선이 보일 만큼만.** `'Pitch'` 기본값 340 → **190**. 다만 칸마다 들어가야
     하는 것이 다르므로 빌더가 아니라 **도구가 재서** 넓힌다 —
     `max(18 + 태그통로, 통로최소) + 13*사슬가닥 + (Gap + 태그폭 + 이름표) + 여백`
   - 로깅·화면·종착 상자는 **사슬 바로 아래**에 붙인다 (`BOX_DROP` 120 → 50)
   - **받기만 하는 종착 블록**(Terminator·Display)은 바닥으로 쓸어내리지 않고 내는 포트
     **바로 오른쪽**에 둔다. 그러면 선이 수평 한 토막이고, 둘이 나란히 내려가며 서로
     겹치고 관통하는 일이 없다 (2026-10-01 W07_1_vrx 의 `EndChi`·`EndU`)
   - 도면이 커지면 PDF 에서 **글씨가 작아진다.** 같은 내용이면 **작은 도면이 낫다**
   - 점검은 눈대중이 아니라 **채움 비율**이다 — 블록 넓이 ÷ 경계상자 넓이

   ```matlab
   check_fill(모델, true)    % 최상위 채움 비율. 합격선 없음 — 전후를 견준다
   ```

   > | `W09_0_offline` | 16.4 % → **24.1 %** | 10 → **9** |
   > | `W09_1_vrx` | 17.0 % → **21.9 %** | 12 → **11** |

   > 한 모델도 늘지 않았다. 수치는 그대로다 — 오프라인 네 모델의 `out` 전 필드를
   > min·max·sum·끝값 10 자리까지 전후 비교해 **전부 일치**했다 (배치만 바뀌었으므로).
   >
   > 좁히다가 두 번 되돌렸다. `Pitch` 190 으로 줄이자 `Guidance -> InnerLoop` 세 가닥이
   > **같은 x 에 포개졌고**(겹침), 넓히자 다시 채움 비율이 떨어졌다. 범인은 간격이 아니라
   > **통로를 하나씩 그으면서 앞 통로를 모른다**는 것이었다 — 통로를 **먼저 다 정하고**
   > 겹치는 것만 13 px 씩 비키게 고쳤다. 그러고 나서야 좁힌 간격이 버텼다.

   >
   > 가장 크게 준 것은 **세로**였다. `lay_chain` 은 상자를 놓을 때 태그 더미가 내려갈
   > 깊이를 미리 잡아 두는데, 그 뒤 `snug_tags` 가 태그를 포트 옆으로 끌어올리므로 그
   > 깊이가 통째로 빈 칸으로 남는다 (`W05_1_vrx` 에서 약 500 px). 그래서 **`pack_boxes`**
   > 를 만들어 `snug_tags` **뒤에** 포트 없는 상자를 사슬 바로 아래로 당긴다. 이 한 줄로
   > 여덟 모델 평균 채움이 17.3 % 에서 21.7 % 가 되었다. 선이 걸린 상자는 건드리지 않는다 —
   > 블록만 옮기면 선의 중간 점이 남아 끝 토막이 사선이 되기 때문이다.

8. **꺾임 2회를 모델별로 세어 보고한다**
   ```matlab
   [n, v, n2] = check_lines(모델);   % n2 = 꺾임 2회인 선의 수
   ```
   - 합격선은 아니지만 교수가 눈으로 보는 지표다. **0·1 회가 목표**
   - 고치기 전후를 모델별로 표로 적어 견준다 (2026-10-01 4주차 15개 합계 208 → 126)
   - 태그가 걸린 선은 위 규칙만 지키면 전부 **0 회**가 된다. 남는 것은 포트가 여럿인
     블록의 팬아웃(Bus Selector → MATLAB Function, → Mux) 처럼 구조상 피할 수 없는
     것뿐이다. 그런 것은 `align_to` 로 한 가닥이라도 직선으로 만든다

9. **로깅은 `To Workspace` 하나.** `Bus Creator` 로 묶고 `SaveFormat` 은 `Timeseries`
   - 그러면 결과가 **필드 이름이 살아 있는 구조체**다 — `out.log.psi` · `out.log.FL`
   - 필드 이름은 버스로 들어가는 **선 이름**에서 온다. 이름을 안 주면 `signal1` 이 된다
   - **로그 변수 이름 = 신호 이름.** `log_psi` 가 아니라 `psi` 다
   - 저장되는 신호의 **개수·이름·값은 그대로** 두고 블록만 줄이는 것이다
   - 꺼내 쓰는 **스크립트와 문서의 실습 명령을 반드시 같이 고친다.**
     `out.log_psi` → `out.log.psi` 를 빼먹으면 학생 손에서만 오류가 난다

### 제어기는 서브시스템 하나로 (예외 없음)

제어기 하나 = **서브시스템 하나**다. 밖에서는 그 상자와 포트 이름만 보인다.

```
HeadingCtrl(psi_ref, psi, r) -> N          헤딩 제어기는 상자 하나
```

상자 **안에** 들어가는 것

- 오차 계산 (`ssa` 같은 각도 wrap 포함)
- 게인 블록, 적분기, 미분기
- 포화·안티와인드업
- 그 제어기만 쓰는 상수 (게인 값, 한계값)

상자 **밖에** 남는 것 — 측정값과 지령, 그리고 출력. 그것뿐이다.

| 왜 | |
|---|---|
| 옮길 수 있다 | 다른 주차 모델로 상자만 복사하면 된다 |
| 읽힌다 | 최상위에서 "무엇이 무엇을 만드는가"만 보인다 |
| 바꿀 곳이 하나다 | 게인을 고치려면 그 상자만 연다 |

> [!caution] 오차 계산 블록을 상자 밖에 두지 않는다
> `HeadingErr` 를 최상위에 두면 제어기가 두 조각이 되고, 최상위에 제어기 내부
> 신호가 떠돌아다닌다. 7주차가 그 상태였다가 2026-09-17 에 고쳤다.

# 읽히지 않는 블록도는 읽히지 않는 코드다

## 한 줄 요약

> 블록도에서 선을 눈으로 따라갈 수 없으면, 학생은 그 모델을 읽는 대신 그냥 Run 버튼만 누른다.

## 무슨 일이 일어나는가

- Simulink 는 블록을 놓은 자리에 그대로 둔다. 자동으로 정리해 주지 않음
- 프로그램으로 모델을 만들면 좌표를 일일이 지정해야 함 → 신경 쓰지 않으면 금세 엉킴
- 엉킨 도면의 증상

| 증상 | 학생이 겪는 일 |
|---|---|
| 선이 큰 블록 위를 가로지름 | 어디서 와서 어디로 가는지 못 찾음 |
| 블록이 겹침 | 밑에 깔린 블록의 존재를 모름 |
| 대각선 | 교차점이 연결점인지 아닌지 구분 안 됨 |
| 주석이 블록 위에 겹침 | 설명을 못 읽음 |
| 모든 블록이 같은 회색 | 유도인지 제어인지 구분에 시간이 걸림 |

- **자동 배치(`arrangeSystem`)만으로는 부족함**
  - 최상위에서는 GNC 순서(유도 → 제어 → 추진기 → 운동모델)를 흐트러뜨림
  - 서브시스템 내부에서는 오히려 잘 동작함 → **층에 따라 다른 전략**을 쓴다

## 왜 중요한가 / 어디에 쓰나

- 이 수업의 모델은 **학생이 열어서 고칠 것**을 전제로 배포함
  - 읽히지 않으면 배포한 의미가 없음
- 규칙을 정하고 **코드로 강제**하면 22개 모델이 전부 같은 모습이 됨
  - 학생은 7주차에 익힌 읽는 법을 9주차에 그대로 씀
- 검증 가능한 목표를 둔다 — **블록 겹침 0쌍**
  - "깔끔해 보인다"는 기준이 아님. 세어서 확인함
  - 실측: 모델 22개 · 블록 659개 · 선 667개 → 겹침 0, 꺾인 선 97 (14.5%)
- 꺾인 선을 0으로 만들 수는 없음
  - 되먹임(Unit Delay 되돌림)은 반드시 뒤로 돌아감
  - 포트 개수가 다른 블록 사이도 높이를 맞출 수 없음
  - **직각까지만 허용하고 대각선을 금지**하는 것이 현실적인 선

## 한 줄 요약

> 좌표계 불일치는 **에러를 내지 않는다.** 코드는 정상 실행되고, 배만 엉뚱하게 간다.

## 무슨 일이 일어나는가

- 쓰는 좌표계가 두 진영으로 갈림

| 진영 | 좌표계 | 축 |
|---|---|---|
| ROS · Gazebo | **ENU** | x=동, y=북, z=위 |
| 선박 · 항공 제어 이론, Simulink | **NED** | x=북, y=동, z=아래 |

- VRX에서 받은 값을 그대로 제어기에 넣으면 축이 뒤바뀜

```
x_n =  y_ENU      psi_NED = 90도 - psi_ENU        r_NED = -r_ENU
y_n =  x_ENU
z_n = -z_ENU
```

- 증상 (NED 기준 헤딩 제어기에 VRX 값을 넣었을 때)

| 빠뜨린 것 | 증상 |
|---|---|
| x(북) · y(동) 교환 | 항적이 x = y 대각선에 대해 거울상. 북쪽으로 보내면 동쪽으로 감 |
| 각도 변환 전체 (psi = psi_ENU 그대로) | 측정각이 90도 − psi 라 증감이 반대 → **되먹임 부호가 뒤집혀** 목표에서 멀어지는 쪽으로 계속 돎 |
| 90도 만 빠뜨림 (psi = −psi_ENU) | 부호는 맞아 안정적으로 수렴하나 헤딩이 정확히 90도 어긋난 채 **그럭저럭 따라감** ← 가장 위험 |
| r 부호 | 감쇠항이 반대로 작용 → 목표 부근 진동 증가 · 발산 |
| z(아래) 부호 | 수평 3자유도에서는 드러나지 않음. 고도 · 깊이를 쓰는 순간 뒤집힘 |

- 발산하는 실수는 바로 발견됨. **안정적으로 틀리는** 90도 누락이 가장 늦게 발견됨

- 왜 발견이 늦는가
  - 파이썬은 타입 에러를 내지 않음. `float` 는 `float` 임
  - **축의 의미는 코드에 적혀 있지 않음**
  - "그럭저럭 되니까" 넘어가고, 조건이 바뀌면 무너짐

## 왜 중요한가 / 어디에 쓰나

- **3주차** 과제가 이 변환 노드를 짜는 것
  - "동작한다"가 아니라 왕복 변환 오차 · 북/동 직진 시 부호 · ±180도 wrap 을 **수치로 증명**하게 함
- **6주차** Simulink 연동에서 다시 나옴
  - `X_pose_config_test_2022a.slx` 는 프레임 변환만 하는 모델
  - 그것이 별도 모델로 존재하는 이유가 이것
- **쿼터니언 순서**도 같은 종류의 오류
  - ROS `(x,y,z,w)` vs MATLAB quaternion 객체 `(w,x,y,z)`
  - 바꿔 넣어도 예외가 없음

- **대책은 하나뿐**
  - 변환 함수를 **한 곳에만** 둠
  - 좌표계를 **변수명과 주석에 박아 넣음** — `psi` 가 아니라 `psi_ned_rad`

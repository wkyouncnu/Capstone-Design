## 한 줄 요약

> 평가하는 것은 "AI를 썼는가"가 아니라 **"AI 출력을 검증했는가"** 다.

## 무슨 일이 일어나는가

- 금지하면 → 학생이 몰래 씀
- 그냥 허용하면 → 검증 없이 붙여넣고 데모 날 터짐. 그리고 **자기 코드를 설명하지 못함**

- 문제의 본질은 도구가 아니라 **책임의 소재**
  - 에이전트는 그럴듯한 코드를 빠르게 만듦
  - **틀린 것도 그럴듯하게** 만듦
  - 자주 틀리는 곳: ROS 2 좌표계 부호, QoS 설정, 단위, 존재하지 않는 API

## 왜 중요한가 / 어디에 쓰나

- 이 수업의 정책은 네 줄

| 요구 | 내용 |
|---|---|
| 프롬프트 로그 | 주요 코드 생성에 쓴 프롬프트를 `docs/agent_log.md` 에 기록 |
| 검증 기록 | 에이전트 초안 → 최종본 **diff + 수정 사유**. 5주차부터 매 과제 |
| 설명 책임 | 발표 시 **자기 코드의 임의 라인을 지목받아 설명**. 못 하면 감점 |
| 책임 소재 | 검증 없이 병합한 코드로 인한 데모 실패는 감점 사유. 변명 불가 |

- 핵심 장치는 **"수정 사유 3가지 이상"**
  - 이것이 학생을 코드를 읽게 만듦
  - 읽지 않으면 고칠 데를 못 찾음
  - 대개 진짜로 고칠 데가 있음

- 부수 효과
  - 초안과 최종본의 diff가 쌓이면 **어디서 AI가 반복적으로 틀리는지**가 데이터로 남음
  - 그것이 다음 학기 강의자료가 됨

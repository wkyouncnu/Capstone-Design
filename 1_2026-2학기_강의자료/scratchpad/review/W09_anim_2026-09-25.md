# W09 실시간 화면 — 실측 기록 (2026-09-25)

작업: `W09_animate.m` 신설, `W09_0_offline` · `W09_1_sensor_rates` 에 Animate 상자 부착.
환경: Windows 11 / MATLAB R2024b Update 9. VRX 는 3주차 경량 모델(`W03_vrx_lite/run_vrx.sh`, `--render-engine-gui ogre`), `ROS_DOMAIN_ID=7`.

> [!warning] 이 날 측정은 **다른 주차(6·7·8) 작업이 같은 PC · 같은 MATLAB 세션에서 동시에** 돌던 중에 이뤄짐.
> 시뮬레이션 시간 기준 값(오프라인)은 영향이 없지만, **벽시계 기준 값(VRX 수신 주기)은 CPU 경쟁으로 오염됨.**
> 그래서 문서 2-8-1 의 기존 표(2026-09-18 · 2026-09-22)는 **고치지 않음.**

조건: `W09_setup` 기본값, 좌 −200 N / 우 +200 N (제자리 좌선회), `T_end` 20 s, `Ts` 0.005 s, `imu_seed` 1.

| GPS 수신 주기 | 20.05 Hz | **20.05 Hz** | 같음 |
| IMU 수신 주기 | 100.05 Hz | **100.05 Hz** | 같음 |
| 자이로 잡음 표준편차 | 0.0091 rad/s | **0.0091 rad/s** | 같음 |

- Animate 상자는 Goto 태그만 받아 가므로 신호 사슬에 손대지 않음 → 네 수치 모두 그대로.

## 2. 캡처

| 파일 | 모델 | 조건 |
|---|---|---|
| `img/W09_anim_offline.png` | `W09_0_offline` | `W09_anim_capture('offline')`, 20 s, VRX 불필요. 20 s 시뮬 / 4.1 s 벽시계 |
| `img/W09_anim_vrx.png` | `W09_1_sensor_rates` | `W09_anim_capture('vrx')`, 20 s, 경량 VRX · 도메인 7. 20 s 시뮬 / 153.8 s 벽시계 (다른 작업과 CPU 경쟁) |

- 둘 다 `W09_animate()` 가 돌려준 핸들로 `exportgraphics(..., 'Resolution', 150)` → 1938 px (2000 이하). `gcf` 쓰지 않음
- 캡처 실행에서 화면에 뜬 값 — 오프라인 GPS 20.05 / IMU 100.05 Hz, VRX GPS 22.75 / IMU 98.55 Hz, `psi_IMU` 45.0°
- VRX 쪽 GPS 22.75 Hz 는 **설계값보다 높다.** 화면을 켜면 그리는 일이 벽시계를 먹어 페이싱이 밀리고,
  `RateMeter` 는 시뮬레이션 시각으로 나누므로 시뮬레이션 1초당 건수가 올라감. **화면을 켠 실행의 Hz 는 표에 쓰지 않는다**

## 3. VRX 수신 주기 — 화면 끔 (`W09_rates_run(20)`)

조건: 경량 VRX, 도메인 7, `animate` 자동 0, 20 s. **다른 주차 작업과 동시 실행 중.**

| 토픽 | 설계값 | 실측 | 비율 |
|---|---|---|---|
| GPS | 20 Hz | 21.45 Hz | 1.07 |
| IMU | 100 Hz | 106.60 Hz | 1.07 |
| wind | 20 Hz | 7.95 Hz | 0.40 |
| 벽시계 | — | 24.9 s (시뮬 20 s) | — |

- 비율이 1 을 넘는 것은 **페이싱이 밀렸다**는 뜻 (벽시계 24.9 s > 시뮬 20 s). CPU 경쟁 때문
- 바람만 0.40 인 것은 문서 2-8-1 의 0.46 · 0.47 과 같은 경향 — 바람 토픽만 비율이 다르다는 관찰은 유지됨
- **이 표는 문서에 싣지 않음.** 깨끗한 측정이 아님

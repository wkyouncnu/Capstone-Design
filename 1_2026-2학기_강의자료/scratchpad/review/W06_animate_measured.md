# W06 실시간 화면 — 실측 기록 (2026-09-25)

내부 기록. 강의자료가 아니다 (스킬 규칙 3).

6주차 `W06_animate.m` 을 4·5주차식 **네 칸 화면**으로 바꾸고 오프라인·VRX 두 장을 캡처했다.

## 1. 환경

| 항목 | 값 |
|---|---|
| MATLAB | R2024b Update 9 (24.2.0.3212159) |
| VRX | 3주차 경량 모델 `W03_vrx_lite/run_vrx.sh lite` (카메라·LiDAR 없음, `--render-engine-gui ogre`) |
| 월드 | `sydney_regatta` |
| `ROS_DOMAIN_ID` | 7 — MATLAB 쪽은 `W06_setup.m` 이 `setenv` 함, WSL 쪽은 `~/.bashrc` 123행 `export ROS_DOMAIN_ID=7` |
| 스폰 | ENU $(x, y) = (-532.2,\ 200.0)$ → 이 설치는 200 쪽. `W06_setup` 기본값 162 와 다름 (규칙 15) |
| 설정 | `W06_setup` 기본값 그대로 — 중심 (20, 40), $r_d$ 25 m, $p_c$ +0.313 (시계방향), $u_{ref}$ 1.5 m/s, `crab_comp` 0, `required_turns` 2, $K_{p\psi}$ 400 / $K_{d\psi}$ 200, $K_{pu}$ 300 / $K_{iu}$ 100, $F_{max}$ 500 |

**게인·유도 법칙·계수는 한 개도 바꾸지 않았다.** 바뀐 것은 화면 함수와 빌더의 태그 목록 한 줄뿐이다.

## 2. 고친 파일

| 파일 | 무엇을 |
|---|---|
| `W06_simulink/W06_animate.m` | 한 칸 → **네 칸**. 인자가 5 개 → 12 개 |
| `W06_simulink/build_w06_models.m` | `addAnimate` 의 태그 목록 (4 개 → 11 개) 과 주석 |
| `W06_simulink/W06_anim_capture.m` | **새 파일.** 5주차 `W05_anim_capture.m` 과 같은 구조 + 지표 반환 |

- 받는 태그 11 개 — `x_n` `y_n` `psi` `psi_ref` `r_dist` `turns` `u` `u_cmd` `gate` `FL` `FR`
- **전부 이미 있던 Goto 태그다.** 모델에 신호를 새로 뽑지 않았고 선이 한 줄도 늘지 않았다
- 목표 반경 $r_d$ 만 태그가 없다 (`Schedule` 의 3번 출력). 5주차에서 `Gate` 출력에 가지를 치다
  `check_lines` 가 걸린 사례가 있어 **가지를 치지 않고** `W06_animate` 안의 `sched_rd` 가
  `Schedule` 과 같은 규칙으로 다시 계산한다 (`Schedule` 은 시각만 보는 순수 함수라 가능)

### 같은 실행에서 뽑은 지표 (`W06_anim_capture` 가 돌려줌)

판정 기준은 `W06_plot` 과 같다 — 원 도달 = 반경 오차가 $0.3\,r_d$ 안에 처음 든 시각,
정착 = 원 도달 30 s 뒤부터 정지까지.

| 지표 | 오프라인 | VRX |
|---|---|---|
| 원 도달 [s] | 12.5 | 12.4 |
| 정지 (gate → 0) [s] | 240.6 | 212.8 |
| 회전수 | 2.00 | 2.00 |
| 정착 평균 반경 [m] | 27.14 | 27.17 |
| 정착 평균 반경오차 [m] | **+2.138** | **+2.172** |
| 정착 최대 반경오차 [m] | +2.248 | +2.210 |
| 정착 평균 $u$ [m/s] | 1.500 | 1.500 |
| 정착 평균 $F_L$ [N] | 267.4 | 265.5 |
| 정착 평균 $F_R$ [N] | 221.8 | 225.7 |

- 반경오차는 **양수** — 항상 원 **바깥**이다. 원 안으로 들어간 적이 없다
  (오프라인 전 구간 최솟값 $r$ = 26.32 m at 25.9 s > $r_d$ = 25)
- $F_L > F_R$ 이 계속 유지됨 = 요 모멘트가 계속 걸려 있음 = 계속 돌고 있다는 뜻
  (5주차 직선 구간에서는 둘이 한 값으로 모였다)
- VRX 정지가 27.8 s 빠른 것은 **초기 선수각이 다르기 때문**이다. 오프라인은 `psi_init` 이
  중심을 바라보게 두고 시작하고, VRX 는 스폰 선수각에서 시작한다 (문서 D-2 의 실측 32.91°).
  반경오차는 0.034 m 차이 — **유도 성능은 시뮬레이터가 바뀌어도 같다**

### VRX 페이싱

| 측정 | 방법 | 값 |
|---|---|---|
| MATLAB 측 RTF | `W06_anim_capture` 안의 20초 프로브 (odom 헤더 시각 ÷ 벽시계) | **1.073** — 이 값을 페이싱으로 씀 |
| 실제 주행 | 260 s 시뮬 / 319.2 s 벽시계 | 실효 **0.815** |

- 프로브는 Simulink 가 돌기 **전에** 재므로 높게 나온다. 주행이 시작되면 모델과 시뮬레이터가
  같은 CPU 를 나눠 쓰므로 떨어진다 (CLAUDE.md §11). 그래도 **프로브 값을 그대로 쓴다** —
  더 높이면 더 나빠진다는 것이 6주차 D절의 실측(0.97 로 올려 실효 0.787)이다

## 5. 기존 수치가 바뀌지 않았는지

화면을 늘리면서 신호를 새로 뽑지 않았고(이미 있던 Goto 태그만 읽음) 게인·구조를 건드리지 않았으므로
값이 바뀔 이유가 없다. 그래도 실제로 돌려서 확인했다.

`W06_setup` (auto_run) 재실행 — **일곱 줄 전부 문서와 동일.**

| 지표 | 문서 값 (B절) | 재측정 |
|---|---|---|
| 원 도달 시각 | 12.5 s | 12.5 s |

| 정착 후 최대 반경오차 | 2.248 m | 2.248 m |
| 반경오차 표준편차 | 0.013 m | 0.013 m |
| 총 회전수 | 2.00 바퀴 | 2.00 바퀴 |

그 표에 섞지 않고 새 절에 자기 조건과 함께 적었다.

## 6. 다음 사람이 걸릴 만한 것

1. **VRX 를 껐다 켜지 않고 이어 돌리면 스폰이 직전 주행의 끝점이 된다.**
   처음 캡처에서 스폰이 $(220.4,\ -519.4)$ 로 읽혔다 — 직전 260 s 주행이 끝난 자리다.
   `W06_anim_capture` 는 ground truth 첫 샘플을 원점으로 쓰므로 그림은 멀쩡해 보이지만
   조건이 문서와 달라진다. 캡처 전에 반드시 VRX 를 재시작했다 (문서 D절 경고와 같은 이야기).
2. **`bash -lc` 는 `~/.bashrc` 를 읽지 않을 때가 있다.** WSL 에 `export ROS_DOMAIN_ID=7` 이
   있는데도 `wsl -d Ubuntu-22.04 bash -lc 'echo $ROS_DOMAIN_ID'` 가 비어 나왔다.
   스크립트로 띄울 때는 `export ROS_DOMAIN_ID=7` 을 앞에 붙였다.
3. **`Schedule` 출력에 가지를 치지 않았다.** $r_d$ 태그가 탐났지만 5주차 `Gate` 사례가 있어
   그리는 함수에서 계산하는 쪽을 택했다. 모델 쪽 시나리오 규칙을 고치면
   `W06_animate` 의 `sched_rd` 도 같이 고쳐야 한다 — 두 곳에 같은 규칙이 있다는 뜻이다.
4. **되돌아보기 한계 `NMAX` 는 4만으로는 모자란다.** 이 함수는 한 스텝에 한 번 불리지 않는다 —
   오프라인 모델은 ode4 (0.05 s) 라 마이너 스텝까지 **초당 80 번** 불린다.
   C-2 시나리오(600 s)를 돌리면 48,000 개가 쌓여 **앞 100 초가 잘려 나갔다.**
   왼쪽 항적이 (0,0) 에서 시작하지 않고, 오른쪽 세 칸의 가로축이 100 s 부터 시작했다.
   20만으로 올려 고쳤다 (오프라인 2,500 s · VRX 10,000 s 까지 남음).
   5주차(240 s → 19,200 개)·7주차는 이 한계에 닿지 않아 증상이 안 보이지만 **같은 코드다.**
   그 주차에서 긴 실행을 넣으면 같은 일이 생긴다 — 확인해 둘 것.
5. **오른쪽 (1) 의 범례는 `northeast` 여야 한다.** `southeast` 로 두면 $r$ 곡선이 $r_d$ 위에
   누운 자리와 겹친다 (첫 캡처에서 실제로 겹쳤다).
